## 1. Current behaviour

- **What is a show?** `zip-filenames` and `persistent-state-mapping` write three root members: `project-metadata.edn` (settings, including bindings), `hardware.edn` (the rig copy **and show-owned group definitions**), `content.edn` (cue/effect chains, calibration copy and zones). `project-files` projects these from one state value, turning off session-owned vibe switches in the copy (`state/persistent.clj:41–86,103–147`). The writer and the reader of older shows agree on those names (`test/laser_show/state/persistent_test.clj:91–96,121–158`; `test/laser_show/routing/legacy_shows/starter.edn:8–11,28–46,62–65`).
- **Save can destroy the file it is trying to save.** `save-to` returns a clean baseline, path and timestamp *before* requesting the write; `:file/save-failed` restores the previous project status only if the write reports failure (`events/handlers/menu.clj:143–167`; `state/persistent.clj:149–156`). `save-to-zip!` opens the destination directly, pretty-prints each value, closes the ZIP and returns true: a printable Java object is not necessarily readable EDN (`state/serialization.clj:25–39,262–282`). A later entry or close failure can also leave a previously good destination truncated. Restoring state cannot restore those bytes.
- **Open can replace the current document with defaults.** `deserialize` reads the first form, returns an EOF keyword on blank input and normally returns `nil` on a reader exception. `load-from-zip` still associates that result under the filename; no entries yields `{}` (`state/serialization.clj:58–69,300–324`). `read-project` passes that map through, and `effect-load-project` treats *any* truthy map as success (`state/persistent.clj:287–298`; `events/core.clj:201–209`). `zip-contents->file-data` merges the per-file maps; missing values default, then `apply-loaded-project` replaces the show, resets the session/history, migrates and marks it clean (`state/persistent.clj:158–182,193–222,224–255`). The [in-memory probe, lines 43–68](../probes/cljfx_state_outcomes_2026_11_23.clj#L43) put an `ActionEvent` in one effect parameter: the ZIP write succeeded, the whole `content.edn` failed to parse, and the unrelated cue disappeared on Open.

## 2. Root cause

The disk boundary confuses **written** with **readable** and **absent** with **present but corrupt**. Defaults are intentional *inside a recognized project*: pre-Z2 hardware lacks `:rig`, old settings lack vibes and old content lacks zones (`test/laser_show/state/persistent_test.clj:241–265,308–314,585–594`). Defaults are not evidence that the selected archive contains a show. There are two commit points to protect: returning replacement app state on Open, and publishing replacement bytes on Save.

## 4. Changes per namespace

1. **`laser-show.state.serialization`** (`state/serialization.clj:1,244–324`). Add **NEW** `:strict?` mode to `load-from-zip` for project paths. Open the ZIP by its central directory (`java.util.zip.ZipFile`); enumerate exact selected names, reject duplicates, read selected entries to completion and check uncompressed size/CRC. Invalid/truncated ZIP, invalid UTF-8, unreadable EDN or ambiguous members fail the read. Skip unrelated members (including binary extras and directories) without interpreting them as EDN. **NEW** private `read-one-edn [entry-name bytes]`: the shared strict rule is one EDN form and then actual EOF (use a private identity sentinel and a second read on the same reader); trailing whitespace/comments are fine. Allow standard EDN tags such as `#uuid`; never install a catch-all tagged-literal reader. Propagate the member name and cause for logging; no partial map, placeholder or error object masquerading as a value.
2. **`laser-show.state.persistent`** (`state/persistent.clj:1,41–86,224–255,277–298`). Put the **NEW** pure `checked-project-files [files]` rule beside the filename mapping. It returns its input or raises a format error naming the member/path. Apply it to the individual members **before** merging/defaulting. `read-project` requests the strict read for the known names and retains its public contract: validated contents or `nil`, logging the reason once. `apply-loaded-project` also checks its input before replacement so a directly supplied completion cannot erase a show.

   | Member | Open contract (proposed) | Save contract |
   |---|---|---|
   | `content.edn` | **Required exactly once.** One map with a `:chains` map and explicit `:cue-chains` and `:effect-chains` maps; `{}` is valid for either grid. Cell keys are `[col row]` integer pairs; cells are maps; `:items`, when present, is a sequence of item maps (`state/domains.clj:492–511`; an active-only effect cell is legitimate, `state/history.clj:133–141`). Later containers `:zone-maps`, `:zones` and `[:chains :projector-effects]` may be absent; when present, check that each is a map. No minimum cue count, UUID-only ID rule or registry lookup. The six pre-Z4 samples use both grid maps, including empty ones (`test/laser_show/routing/legacy_shows_test.clj:29–32`; `test/laser_show/routing/legacy_shows/timeline.edn:18–28,67–72`). | Must be present, pass the same checks and read back as the projected data. |
   | `project-metadata.edn`, `hardware.edn` | **Optional if absent on read; valid if present.** Preserve the missing-path defaults (`state/persistent.clj:59–86,158–173`). If present, each must be one readable map, and its mapped container fields must be maps when supplied. A damaged companion is a failure, not permission to silently lose bindings or group definitions. Do not require `:rig`, new settings, current target keys or all three chain types from an old show. | **Both required on every new Save**, including the full rig copy (`test/laser_show/state/persistent_test.clj:509–515`). Check every projected member, not just `content.edn`. |

   The optional-companion rule is read compatibility, not a claim that the checked-in old writers omitted those files. A metadata-only ZIP, foreign ZIP, non-ZIP or wrong-shaped content does not qualify. The config-default test supplies only metadata directly to a handler; the session-reset test supplies `{}` directly to the reducer (`test/laser_show/events/menu_file_handlers_test.clj:194–203`; `test/laser_show/state/persistent_test.clj:398–405`). Supply valid, explicitly empty grid maps to **those fixtures**; keep their original assertions.

3. **Publish the file in `write-project!`** (`state/persistent.clj:277–285`). Create the destination directory and a unique temporary sibling. Write the three projected members there with the existing UTF-8 writer and unbounded, readable printing; finish and close the archive. Require the encoder to return true **and** `read-project` of that exact sibling to return all three members equal in EDN value to the supplied projection (before migrations). Thus an object, an omitted member, or even readable-but-different output fails. **NEW** private `publish-project! [staged target]` is the single, testable commit point: atomic replacing move on the same filesystem. If the filesystem cannot replace atomically, report Save failure; never delete/truncate the destination to retry. All pre-publication errors return false and remove the sibling in cleanup; log a cleanup error separately. A rejected Save As leaves an absent destination absent.
4. **`laser-show.events.handlers.menu`** (`events/handlers/menu.clj:1,98–167,191–204,236–247`). Extract **NEW** pure `prepare-open [state contents file-path]` from the replacement and rig-report construction at `events/handlers/menu.clj:122–135`. Open returns its candidate state only if the whole preparation succeeds; on a data-dependent validation, migration or report error, return `:dispatch` of the existing load-failed event instead. Save uses the same preparation as a dry run on the projected files and current rig: even readable EDN that this build cannot open must not replace the old file. Discard the candidate; Save never resets the session. `save-to` returns the passed state on both branches (including a just-closed confirm dialog). A projection/preparation error adds only `:dispatch` of `:file/save-failed` with the path; success requests the ZIP write with files, failure callback and optional `:on-saved` continuation. Remove the optimistic mark and `:previous-project` rollback payload.
5. **`laser-show.events.core`** (`events/core.clj:1,188–209`) and **`laser-show.events.handlers.files`** (`events/handlers/files.clj:1,12–18`). Only after publication does `effect-save-project` run `:project/mark-clean` inline, with **NEW on that event** `:file-path` and optional `:then` from `:on-saved`. Its handler calls `mark-saved` with the successful path and time co-effect, then returns `:dispatch` for `:then` if supplied (retain pathless mark-clean behaviour). Write failure runs only `:file/save-failed`, which now just returns the notice (`events/handlers/menu.clj:157–167`).

## 7. Data examples and invariants

`A.zip` is a previously saved, readable show; its edited in-memory version has one extra cue, a nonempty undo stack and a `*` in the title. The paths and event shapes below are those in §§4–6.

| Input | Expected outcome |
|---|---|
| Open `B.zip`: readable companions; raw `content.edn` text `{:chains #object[java.lang.Object 1 "x"]}`. Same refusal for missing content, `nil`, `[]`, `{:chains {:cue-chains [] :effect-chains {}}}`, or a second EDN form after valid content. | `read-project` → `nil`; `:file/project-load-failed` → “Could not open B.zip”. Still editing A with the same project metadata, cue, selection and undo/redo. No rig report or reset. |
| Open `B.zip`: `{"content.edn" {:chains {:cue-chains {} :effect-chains {}}}}`, plus an unrelated binary thumbnail. | Valid **empty** show; missing companions/defaultable fields take their defaults. B opens clean, both grids empty. If a supplied `hardware.edn` instead contains broken EDN, reject the whole Open. |
| Save A with an actual Java object at `[:chains :effect-chains [0 0] :items 0 :params :amount :value]` (probe lines 49–57 above); pending `{:event/type :file/exit :force? true}`. | `write-project!` → `false`; old A bytes still reopen. No mark-clean, no exit, same prior path/time/baseline/history, dirty edit retained; “Could not save A.zip”. The **string** `"#object"` in a cue name is ordinary data. |
| Save As `B.zip` over an existing good B; staging and read-back succeed but the atomic move throws. | Failure; B is byte-for-byte its prior version, A is still current and dirty, no temporary sibling remains and no continuation runs. |
| Save A with `:value 0.42` (same field) and an unrelated named cue, pending Exit. | All three members read back equal to the projection; A is replaced, then marked clean, then Exit is requested exactly once. At the exit hook the new archive is already readable and still contains the cue and `0.42`. |

## 9. Scope

**#01** owns typed numeric events and the real Enter → Save → Open UI regression ([audit, line 58](../2026-11-23-cljfx-reactivity-audit.md#L58)); this boundary must also work for bad data from another producer. **#20** owns stale chooser/document identity and destructive continuations after an intervening edit ([audit, line 79](../2026-11-23-cljfx-reactivity-audit.md#L79)). This plan requires neither to land first. Format versioning, a new backup/recovery format, rig-file changes and background ZIP I/O are separate from accepting or rejecting the current file format.
