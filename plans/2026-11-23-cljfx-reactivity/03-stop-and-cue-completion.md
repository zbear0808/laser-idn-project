# 03 — Keep Stop in force when a cue ends

**Status:** Proposed · **Last verified against:** `7b320b3` (2026-11-23; real handlers and synthetic clock steps).

**Supersedes / Superseded by:** none · **Related findings:** [Stop → cue-ended](../2026-11-23-cljfx-reactivity-audit.md#device-and-runtime-boundaries); [15: timecode chase pruning](15-timecode-chase-lifetime.md). Source paths below are relative to `src/laser_show/`; `T/` means `test/laser_show/`.

## 1. Current behaviour

Stop closes the transport gate (`[:playback :playing?]`), clears the legacy `:active-cue`, keeps the intents in `:active-cues`, and posts a fresh restart request. Retrigger posts the same kind of request without changing the gate; both land pending map/style switches (`events/handlers/timing.clj:30–34,75–110`). A held cue here means **an intent retained by Stop**. The cue's own decay hold (`:hold?`) is a separate control (`animation/cue_timing.clj:331–346`).

The `show-clock` thread takes one state snapshot per tick at 60 Hz. It steps the runs even while stopped; the gate is consulted *after* that step (`services/show_clock.clj:2–7,68,266–289`). A non-looping timeline at its end, or a released cue past its decay, sets `:ended?` (`animation/cue_timing.clj:174–193`). The report contains only `:cell` and `:run`; the event handler checks the run, then `deactivate-cue` sets the gate from the remaining intents alone (`animation/show_time.clj:227–229`; `events/handlers/timing.clj:160–166`; `animation/cue_timing.clj:348–355`).

**Rechecked:** Starting a 16-beat timeline at 15.9 and keeping a second ordinary cue, `show-time/step` at 0 and 100 ms (120 BPM) produced an end. Holding that event, processing Stop, then delivering it gave **playing: 2 cues → stopped: 2 held → playing: 1 cue**, reproducing the [audit fixture](../probes/cljfx_state_outcomes_2026_11_23.clj#L70-L74). In separate runs, a seek to beat 2 and a transport retrigger each kept the same run ID; the old event removed the cue in both cases. Without it the next step at the same timestamp put the cue at beat 2 and beat 0, respectively. A genuine end of the *only* playing cue already left an empty map and `false`.

## 2. Root cause

There are two independent decisions: **is this still the position that ended?** and **what happens to the gate after removing it?** The current run check rejects a replacement run, but a seek or global restart clears `:ended?` **without replacing the run** (`animation/cue_timing.clj:276–290,357–368`; `animation/show_time.clj:108–117,146–166`). A *fresh* end can also arrive after Stop reset the clocks and a timeline finished again: in a 0.25-beat fixture the pre- and post-Stop reports were equal maps. Fixing only report identity would still reopen the gate then. Ignoring every end while stopped would leave finished intents in the held count.

## 4. Changes per namespace

1. **`laser-show.animation.cue-timing`** (`animation/cue_timing.clj:1,331–368`): change `deactivate-cue [playback cell]`. An absent cell is a no-op. On real removal, keep the previous gate if any intent remains; otherwise set it to `false`. Keep `:active-cell` when a different cell ends; if the focused cell ends use the existing first remaining key, or `nil` on the last removal. Leave all surviving intents intact. Add **NEW** pure `position-ids [playback cell]`: project exactly `{:restart <global restart request id> :seek <this cell's seek request id>}`. Sharing this one projection prevents the sender and receiver from using different IDs. Both entries are present, including `nil` before the first corresponding request.
2. **`laser-show.animation.show-time`** (`animation/show_time.clj:1,210–235`): add **NEW report field** `:position-ids` to each existing `:show-clock/cue-ended`, using the playback snapshot the step just applied. Do this at report creation, never by rereading app state at dispatch. Don't stamp the last value of runtime `[:applied :restart]` unconditionally: it remembers an earlier request even when a new document has none (`animation/show_time.clj:126–136`; `state/persistent.clj:193–205`; `T/animation/show_time_test.clj:204–223`). A fresh run in that document reports `:restart nil`. A new position that ends within the old report's retry window is a different report; retries of the same end remain identical.
3. **`laser-show.events.handlers.timing`** (`events/handlers/timing.clj:1,160–183`): consume the enriched event. Require a current non-chasing intent at the reported cell, a **non-nil** run equal to its run, and exact equality of the full `:position-ids` map with the projection of the handler's current playback. Skip a definition now following timecode; that handoff belongs to chase (`timeline/playback.clj:53–56`; `animation/show_time.clj:141–145,168–180`). For a mismatch, missing field, missing cell, or duplicate, return `{:state state}` unchanged. Two missing run IDs do not identify a cue. Only a match calls the shared removal helper, once.
4. **`laser-show.state.domains`** (`state/domains.clj:1,57–84`): correct the `:playing?` description (“any cues playing”); a stopped transport can have intents, and Play can open an empty transport. No schema change.

## 7. Five data examples and invariants

`A` = `[0 0]`, `B` = `[1 0]`; `r`, `b`, `K1`, `K2`, `S1`, `S2` stand for distinct UUIDs. State is projected as `[playing? {cell run} active-cell]`. `end(A,r,K1,S1)` denotes the event `{:event/type :show-clock/cue-ended :cell [0 0] :run r :position-ids {:restart K1 :seek S1}}`.

| Before → events in handling order | Expected state / observation |
|---|---|
| `[true {A r B b} A]`; clock observed `end(A,r,nil,nil)`; Stop writes `K1`; deliver that old end | `[false {A r B b} A]`. Both intents still held; no completion of the restarted position has been observed. |
| `[false {A r B b} A]`, restart `K1` applied; genuine `end(A,r,K1,nil)` twice; then Play | First `[false {B b} B]` (held count 1, playing list `[]`); duplicate unchanged. Only Play changes this to `[true {B b} B]`. |
| `[true {A r B b} A]`; `B` finishes its released decay, then timeline `A` ends, both current | `[true {A r} A]` → `[false {} nil]`. A duplicate after a later Play on the empty transport leaves `[true {} nil]`. |
| `[true {A r} A]`, restart `K1`, seek `S1`; clock queues `end(A,r,K1,S1)`; seek to beat 2 writes `S2`; deliver queued end | `[true {A r} A]` with `{:id S2 :beat 2.0}` still requested. A later `end(A,r,K1,S2)` is accepted, leaving `[false {} nil]`. |
| `[true {A r} A]`, `K1` and `S1`; clock queues an end; Retrigger writes `K2` with the same `r` and `S1` | Delivering `end(A,r,K1,S1)` leaves `[true {A r} A]`. `end(A,r,K2,S1)` from the restarted run removes the last cue, even if the two reports are less than 250 ms apart. |

**Invariants:** cleanup can close the gate but never open it. The last-*removal* rule does not continually force an empty transport off. Seek invalidates only that cell's old position; restart invalidates all old positions; other cells' seeks and phase align/shift do not revive an ended run (`animation/show_time.clj:108–136`). Moving or replacing the cue never authorizes cleanup at the old address. A missing fingerprint is not a wildcard, and a retry must not acquire the identity of a newer seek or restart.

## 9. Boundary with #15

**Land #03's shared removal rule before integrating [#15](15-timecode-chase-lifetime.md).** Today `:show-clock/chase` is produced alongside ends, sent by the same dispatcher, and routed separately (`animation/show_time.clj:201–205,230–235`; `services/show_clock.clj:300–305`; `events/handlers/timing.clj:168–183,299–301`). #15 owns pruning and validating that an inactive report still names the intent it observed before calling `deactivate-cue`. With a second cue held after Stop, even a matching chase-off must leave the gate closed. Keep the existing takeover case where timecode was enabled on a *manual* run and is stopped (`T/animation/show_time_test.clj:420–431`); it must not remove a newer manual run at that cell. A chase intent has no manual run ID (`state/domains.clj:74–82`), so chase-off cannot masquerade as cue-ended. Clock advancement, output and hardware are outside this work package.
