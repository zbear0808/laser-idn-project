# 07 · Keep both edits to a modulator’s range

**Status:** Implemented in `2e5703a` on `reactivity/integration` (2026-11-24); see [implementation status](00-overview.md#implementation-status-2026-11-24). Planned as: Proposed · **Last verified against:** `7b320b3`

**Supersedes / Superseded by:** None · **Related findings:** [reactivity audit, field edits](../2026-11-23-cljfx-reactivity-audit.md#L65), [improvement review 02 #12 and its toggle fix](../2026-11-07-improvement-review/02-events-state.md#L98-L104).

## 1. Current behaviour

**Reproduced at `7b320b3`:** render an active Triangle with Min `0.2`, Max `0.8` and Period `7.0`. Use the Min and Max slider event maps from **that one description**. Set Min to `0.3`, then Max to `0.9`. The stored ranges were **`[0.2 0.8] → [0.3 0.8] → [0.2 0.9]`**. This was a headless, in-memory check of the real control descriptions and the two real handlers; no timing assumptions. Source paths below are relative to `src/laser_show/` unless prefixed with `test/` or `docs/`.

- The wave declares separate Min and Max fields (`animation/modulators.clj:47–56`). Each slider sends its own `:mod-param-key` and cljfx supplies the new value (`views/components/modulator_param_control.clj:109–131`). But their shared event template already contains the **entire** rendered modulator as `:current-value` (`views/components/modulator_param_control.clj:439–447,520–526`). The visual editor and modulatable choice build the same template (`:392–403,606–611` in that file).
- `:modulator/update-param` associates the new subfield into that old map and dispatches the whole result as `:chain/update-param` (`events/handlers/modulator.clj:121–125,152–166,220–225`). The chain route replaces the parameter at the supplied vector path (`events/handlers/chain/core.clj:63–64`; `events/handlers/chain/params.clj:81–96`). Two other writers can put old bounds back: `:modulator/set-type` copies the rendered Min/Max into the new type’s defaults; `:modulator/update-static-value` associates the static `:value` into a rendered inactive config (`events/handlers/modulator.clj:53–91,180–207`).
- **Already fixed:** `7b320b3` changed **Modulate**, `:modulator/toggle`. Enabling it reads the effect’s *stored* parameter, disables active keyframes and enables the configured modulator in one `:state` result (`events/handlers/modulator.clj:32–51`). Its three control templates no longer send `:current-value` (`views/components/modulator_param_control.clj:351–354,435–438,579–585`). “Toggle Modulation” already has one undo step and immediate Undo/Redo coverage (`events/handlers/history.clj:156–158`; `test/laser_show/events/history_handlers_test.clj:363–386`; `test/laser_show/ui_test/modulator_editor_test.clj:63–82`). There is no delayed toggle write to repair here.

## 2. Root cause

The callbacks describe **replacement values** when the user edited **one field**. The `:dispatch` above runs inline, not on the old 10 ms timer (`events/core.clj:175–186,719–721`). Serial execution gives the second handler fresh `:state`, but it uses its payload instead. The address is also a snapshot: the shared editor has the effect instance yet emits a vector `:effect-path`; for cue items and timeline owners this includes their positions before `:effects` (`views/components/effect_parameter_editor.clj:43–52,138–154,164–179`). Re-reading the latest config at that *old index* could edit the replacement occupant.

## 4. Changes per namespace

1. **Identify the instance while rendering.** In `views/components/effect_parameter_editor.clj:76–109,164–167,256–271,279–287`, add the effect’s `:id` as `:effect-instance-id` to both standard and custom modulator event bases. For an owned effect, also pass **NEW** `:owner-id`: the cue item’s `:id` (`views/dialogs/cue_chain_editor.clj:57–81`) or clip/track/folder’s `:id` (`views/components/visual_editors/timeline/device_chain.clj:38–46,77–87`). The effects-cell and cue-pattern editors already pass the instance (`views/dialogs/effect_chain_editor.clj:47–64`; `views/dialogs/zone_pattern_editor.clj:25–43`). The Step Grid toolbar is a separate producer (`views/components/step_grid.clj:364–373,395–404`); pass the **displayed pattern’s ID**, already available from `subs.clj:1334–1347`. Integrate with [05’s window target](05-step-grid-target.md), so the toolbar and window name the same instance.
2. **Build field intents.** In `views/components/modulator_param_control.clj:334–359,381–404,424–457,508–518,563–611`, use one **NEW** private `field-event [base event-type param-key]` to select the stable address for the three writers in §6. This keeps numeric, choice and visual templates in step. Keep `:current-value` as *display data*. The field intent contains neither it nor `:effect-path`. Value-change maps can use the existing `:value :fx/event` placeholder (`events/core.clj:607–625`). For the type dropdown send the selected `:id`, not the registry item; the FX callback must actually dispatch (`views/components/modulator_param_control.clj:63–75`; `events/core.clj:811–835`). Use [01’s numeric commit boundary](01-numeric-commits.md) for typed numbers. For the palette/text controls (`views/components/modulator_param_control.clj:189–199,218–227`), pass submitted text as data and retain the existing list/text interpretation (`events/handlers/modulator.clj:102–108,135–151`).
3. **Resolve against the handler’s co-effect.** Add **NEW** `resolve-effect-instance-path [state address]` in `events/handlers/chain/helpers.clj:14–50`, shared by the writer and Show Lock. Require a supported domain, entity key and non-nil instance ID. In `:effect-chains`, `:cue-zone-patterns` and `:projector-effects`, match `:effect-instance-id` to the stored `:id` in the configured vector. In `:cue-chains`, `:timeline-items` and `:timeline-tracks`, first find the required owner ID in that root, then find the instance ID within the owner’s `:effects`, using the grouped lookup at both levels. Return a relative path to the matching effect, or nil. Never fall back to the old slot, current selection or another cell. In `events/show_lock.clj:95–116,155–173`, classify these three intents by that resolved effect in an effects cell: a moved pattern is still protected and a point effect is not refused because a pattern occupies its old slot. Keep the existing cue-pattern-domain lock rule.
4. **Apply the field in one turn.** Change `handle-update-mod-param`, `handle-set-type` and `handle-update-static-value` (`events/handlers/modulator.clj:53–91,110–166,180–207`) to read the resolved effect’s **base** `[:params param-key]` from `:state`. Require the effect and parameter to exist and keyframes to be off (`views/components/effect_parameter_editor.clj:143–154`; `events/handlers/keyframe.clj:146–173`). Apply the per-event rule in §6. Missing target, incompatible mode/config/subkey, invalid input or an equal result returns `{}`. For a change, return the new `:state` directly. An old callback cannot create a parameter, enable modulation or edit keyframes.

## 7. Data examples and invariants

`A` and `B` denote distinct instance IDs for the same `:effect-id :intensity`; `P` is an owner ID. Field pairs below stand for the intent above. Expected maps show only the named keys; tests compare the rest of the document too.

| Before / queued edit | Expected after handling |
|---|---|
| `A {:type :triangle :period 7.0 :min 0.2 :max 0.8}`; `[:min 0.3]`, `[:max 0.9]` from one render | `{:type :triangle :period 7.0 :min 0.3 :max 0.9}` in either order. Two accepted writes to the *same* field take the last value. |
| Same render: `[:max 0.9]`, then select `:square` | `{:type :square :min 0.2 :max 0.9 :duty-cycle 0.5}` among the new defaults (`animation/modulators.clj:58–68`). A later field absent from the current type’s definition is ignored. |
| Rendered `P` at `[0]`, its effects `[A B]`; now `P` at `[1]`, effects `[B A]`; patch `P/A :amount [:min 0.3]` | Change `[1 :effects 1 :params :amount :min]` under the current root. `B`, the item at `[0]`, and the order are unchanged. |
| Rendered `[A B]`; now `[B]`; queued `A :amount [:max 0.9]` | `[B]` exactly as before handling. Same result if the owner, cell or parameter was deleted: no placeholder, undo entry or dirty change. |
| Inactive slider rendered with `:min 0.2`. At delivery the stored config is `{:type :triangle :active? false :min 0.3 :max 0.9 :period 7.0 :value 0.4}`; commit static `0.6`. | Only `:value` becomes `0.6`; in particular Min stays `0.3`. A stale active Max edit against this inactive config is ignored, as is the inactive edit if the config has since been re-enabled. |

Editing a subfield preserves every sibling, including a remembered static value. Min and Max use the parameter’s existing bounds (`views/components/modulator_param_control.clj:268–279`); do not sort them or constrain one against the other. An Envelope’s peak below its rest is intentional (`animation/modulators.clj:89–97`).
