# 08 · Commit one safety-zone coordinate without losing another

**Status:** Proposed · **Last verified against:** `7b320b3` (2026-11-23, offline handlers and headless controls)

**Supersedes / Superseded by:** none · **Related findings:** [reactivity audit, field edits](../2026-11-23-cljfx-reactivity-audit.md#L65); [Z1’s unreadable-zone editor](../2026-11-19-zones/03-phase-z1-safety.md#L406-L410); [Show Lock decision Q-Z1-5](../2026-11-19-zones/10-questions.md#L77-L85). Source paths below are relative to `src/laser_show/`; `T/` means `test/laser_show/`.

## 1. Current behaviour

**Two committed fields from one render lose the first edit.** At HEAD, starting with `{:limit [-0.5 -0.5 0.5 0.5] :blocked []}`, I took the real `:on-commit` callbacks for `x0` and `y1` from that same zone, submitted `"-0.4"` and `"0.3"`, then passed each event to the real handler with the preceding result as its state. The final limit was **`[-0.5 -0.5 0.5 0.3]`**, not `[-0.4 -0.5 0.5 0.3]` (`views/components/safety_editor.clj:169–205`; `events/handlers/projector.clj:698–726,854`).

Two more offline checks matter for the fix:

- **Pending Allow:** with the same initial zone and the fixture’s outputting flag set, `x1 → 0.75` asked. A tightening `x0 → -0.4` applied while the question was open. Processing the real Allow and its continuation restored `x0` to `-0.5`. The dialog parks a **whole replacement**, and the confirmed write does not compare it with the zone that was reviewed (`events/safety_guard.clj:35–49`; `events/handlers/ui.clj:84–96`; `events/handlers/projector.clj:703–716`).
- **Unreadable is not absent:** for stored `{:limit [0 0]}`, the warning says to Reset. Drag start, Add and the copy menu check readability, but the fields still use the displayed fallback (`views/components/safety_editor.clj:235–260,277–282,301–342`). Submitting `y1 → 0.3` from that fallback changed the unreadable value to `{:limit [-1.0 -1.0 1.0 0.3] :blocked []}` in the offline handler. Conversely an absent or nil `:safety` on a real projector **is** a valid default. `normalize` defines the distinction; an exception in the final safety stage produces an empty result (`animation/safety.clj:19–21,53–81`; `backend/multi_engine.clj:133–149`).

## 2. Root cause

Enter/focus loss already extracts the field’s text and dispatches its returned event (`views/components/commit_field.clj:57–95`). But the coordinate callback puts the value into the **rendered** `zone` and sends that entire map as `:projectors/set-safety`. Serial processing on `laser-show-events` supplies a fresh `:state`; it cannot recover which one of the replacement’s numbers was intended (`events/core.clj:674–679,764–784,811–835`). There are two distinct freshness requirements: **merge ordinary edits** with newer siblings, but **never transfer an Allow** to a different before/after change.

## 4. Changes per namespace

1. **Field and Reset controls** (`views/components/safety_editor.clj:176–205,235–250,277–300,301–334`). Give a field its displayed number, projector ID and a closed-form coordinate address. Its commit returns the first event in §6, never a replacement zone. Enable fields only for a present projector with a readable stored configuration. The fallback is for drawing; a resettable, unreadable projector keeps its warning and explicit Reset. Key a field’s applied display to its own address, value, readability and question state rather than destroying a sibling’s draft on every zone change. Keep Enter, blur and refusal restoration.
2. **Form the proposal once, in data.** In `events/safety_guard.clj:1–19,35–49` add **NEW** pure `zone-edit-proposal [state intent]`, shared by the writer and Show Lock so they evaluate the *same* transition. Resolve the named projector, not the selection. For a field: normalize its current stored config; refuse if missing/unreadable. Accept only the exact vector `[:limit k]` or `[:blocked i k]`, integer `k` in `0..3`, integer `i` naming an existing row **in the current normalized vector**, and a finite number in `[-1,1]`. Never use an arbitrary state path, append at `count`, clamp an invalid input or create missing containers. Replace that one number, normalize the complete candidate, and refuse on exception or if ordering it would move another endpoint. An equal normalized result is a no-op, including an implicit default: do not materialize it. For **Reset**, propose `default-safety` for this projector even when the old value is unreadable. Hand back before/after values for policy, never commit here.
3. **Distinguish a blocked row from its slot.** The document’s rows have no IDs (`animation/safety.clj:5–8,73–81`); removal shifts later rows (`events/handlers/projector.clj:745–758`). Bounds alone would let an old “Blocked 1” field edit the former Blocked 2. Add **NEW** pure `wrap-safety-versions [handler]` in `events/safety_guard.clj`, immediately outside history/dirty in `events/core.clj:645–653`. It stamps *applied* changes in the session data in §5. Skip identical projector roots. An accepted coordinate changes the geometry version but preserves row identities, including for a second field of **the same** rectangle. Add/remove, copy, whole-zone replacement and restore that change the blocked collection invalidate its layout, even for a replacement of the same length. A limit-only change does not invalidate blocked addresses. Remove a deleted projector’s entry; a newly inserted projector gets fresh versions. Stamp actual results, not attempted edits or status reports. This single hook also sees Undo/Redo and rig replacement; no saved row IDs or writer-by-writer bookkeeping.
4. **Apply through the existing gate.** Add **NEW** `handle-projectors-set-safety-coordinate [event]` and `handle-projectors-reset-safety [event]` beside `handle-projectors-set-safety` (`events/handlers/projector.clj:698–728`); register both in `handle` (`:817–822,852–857`). Use the proposal and `write-zone`’s existing refusal/ask/commit branches; extend that helper for a scoped question (§6). Give it a validated answer rather than trusting a payload flag for these two intents. Reset resolves the canonical default in the handler, never four coordinate writes. Keep `:projectors/set-safety` for whole-canvas gestures (`views/components/safety_editor.clj:277–300`); now that Reset is distinct, a queued gesture must also refuse an unreadable **current** base. Add/remove/copy/mirror remain their existing operations (`events/handlers/projector.clj:728–780`).
5. **Classify the two new routes in Show Lock and history.** Add them to `safety-edits`, **not** the blanket blocked set (`events/show_lock.clj:32–49,120–126`). For them, compare the shared proposal’s before/after with `widens?` even when not outputting. The existing dry run injects `:confirmed? true` (`:146–153`): if the new handler correctly distrusts a bare boolean, that dry run alone would miss a locked widening. Use its current-state proposal directly; retain the existing dry run for the other safety events. Register “Change Safety Zone” and “Reset Safety Zone” in `events/handlers/history.clj:148–152,170–175`.

## 7. Five input → output examples

`Z` = `{:limit [-0.5 -0.5 0.5 0.5] :blocked []}`. “Outputting” below means **fixture data only**. Each assertion also compares untouched projectors, sibling coordinates and row order.

| Current configuration and intent(s) | Expected result |
|---|---|
| `Z`; from one render, `[:limit 0] → -0.4`, `[:limit 3] → 0.3` | In either order: `{:limit [-0.4 -0.5 0.5 0.3] :blocked []}`. Undo the second commit: the first survives. A duplicate of the already-applied value adds no undo entry. |
| `Z` with `:blocked [[-0.2 -0.2 0.2 0.2] [0.3 0.3 0.4 0.4]]`; same-render edits to row 0, `x0 → -0.3`, `y1 → 0.25` | Row 0 becomes `[-0.3 -0.2 0.2 0.25]`, row 1 unchanged. If row 0 was removed **before** either edit, row 1 now occupies slot 0 but the layout stamp differs: neither edit lands there. |
| Outputting `Z`; `x1 → 0.75`; then tighten `x0 → -0.4` while the question is open; Allow the old question | First ask leaves `Z` in force. Tightening applies. Stale Allow leaves `[-0.4 -0.5 0.5 0.5]` and creates no undo entry. Re-enter `0.75`, answer the **new** question → `[-0.4 -0.5 0.75 0.5]`. An old click cannot answer the new question. |
| Locked `Z`, whether outputting or not: `x1 → 0.75`; `x1 → 0.4` | First: existing “Larger safety zone refused” notice, no question or edit. Second: `[-0.5 -0.5 0.4 0.5]` immediately. If the lock was turned on between an unlocked question and Allow, the same refusal wins. |
| `{:limit [0 0]}`; queued `[:limit 3] → 0.3`; explicit Reset | Field leaves the **original unreadable value** untouched, even from a once-valid control. Unlocked Reset while off yields `{:limit [-1.0 -1.0 1.0 1.0] :blocked []}`; while outputting it first asks; locked it refuses. A missing projector stays missing. |

**Invariants:** The current normalizer still accepts nil/default, orders/clamps existing rectangles, rejects nonfinite coordinates and zero-area **limits**, and preserves tiny or more-than-eight imported blocked rectangles (`animation/safety.clj:47–81`; `T/animation/safety_test.clj:18–41`). The eight-entry ceiling is an **Add** rule (`events/handlers/projector.clj:728–743`), not permission to truncate a list during editing. Reject a crossed endpoint on a **single-field** intent rather than silently swapping its sibling; whole-zone normalization keeps its present semantics. Pending, cancelled, invalid, stale and lock-refused intents never change rig content, undo/redo stacks or show dirty state. Two valid committed edits to the same field are ordered by handling time; distinct edits commute whenever both intermediate zones are valid and their required approvals are current.
