# 10 — Resolve a cue-grid click against the current cell

**Status:** Proposed · **Last verified against:** `7b320b3` (2026-11-23; headless click callback, real selectors and handlers).

**Supersedes / Superseded by:** none · **Related findings:** [queued cue click](../2026-11-23-cljfx-reactivity-audit.md#L66); [events review Q13, duplicated grid handlers](../2026-11-07-improvement-review/02-events-state.md#L234). This page owns the grid part of Q13.

Source paths are relative to `src/laser_show/`; `T/` means `test/laser_show/`.

## 1. Current behaviour

The Grid tab renders one cue cell per zero-based `[col row]` (`views/tabs/grid.clj:19–34`; `views/components/grid_tab.clj:93–102,114–125`). Its `grid-cell` subscribes to `subs/cell-display-data` and supplies `:grid/cell-clicked` to `generic-grid-cell`. The primary single-click callback dispatches **coordinates plus the rendered `:has-content?`** (`views/components/grid_cell.clj:133–139,153–178,294–299,377–387`). `events/dispatch!` queues the map in the running app (`events/core.clj:811–831`). `handle-grid-cell-clicked` selects the coordinate and branches on that flag (`events/handlers/grid.clj:100–131`).

**Reproduced in both directions.** In a fresh headless JVM, a real primary `MouseEvent` was passed to the cue cell's callback. Its dispatched map was retained and given to the grid handler with the *later* state. At `[2 1]`, rendering a nested preset on a stopped transport, then processing Clear before the click, produced **no cue definition, but a new run UUID, `:playing? true` and cue pulse ID 1**. Rendering empty, then filling the coordinate with the same preset before handling the click, produced **selection only, no run or pulse**. Clear removes the definition and active entry; it does not itself set `:playing?` (`events/handlers/grid.clj:178–187`; menu dispatcher `views/components/grid_cell.clj:340–343`). These are intent/pulse observations; the clock's render list omits chains without items (`animation/show_time.clj:301–318`).

External input has a different error. A discrete input dispatches `:trigger/input`; its ordinary `:trigger-cue` press emits `:grid/trigger-cell`, and a `:momentary` binding emits `:grid/activate-cell` on press and `:grid/release-cell` on release (`events/handlers/input_mapper.clj:94–110`; `events/handlers/triggers.clj:65–79,128–141,178–185`). **Both start-capable handlers test for a truthy cell map.** In the same probe `{:name "Draft"}`, `{:items []}` and `{:items [{:type :group :items []}]}` each displayed `:has-content? false`, yet both external press paths started a run and pulsed. For a *missing* cell the ordinary press already selects it, whereas a momentary press leaves even selection unchanged. Release checks the active entry, not the definition (`events/handlers/grid.clj:59–93`).

## 2. Root cause and decision

The queued bit answers **what the last render saw**. Map presence answers **whether the document has an entry**. Neither answers whether the addressed cell currently has cue-grid content. The selector already defines that: **a configured timeline, or at least one stored `:type :preset` at the root of `:items` or under `:type :group` items**. It counts disabled presets and descends through disabled groups. A name, mode, empty group or untyped leaf alone does not count (`subs.clj:269–291`). `timeline-cue?` accepts explicit `:timeline` even without clips; absent an explicit editor choice, tracks or top-level clip timing/track keys can imply a timeline. Explicit `:cue-chain` suppresses that inference (`animation/cue_chains.clj:59–75`).

Use **one coordinate intent** for an ordinary press, `{:event/type :grid/trigger-cell :col 2 :row 1}`, and **one plain-data content predicate** shared by display and grid handlers (§4). The coordinate, not a cue UUID, is the target: if content is replaced there before handling, act on its replacement. Content permits a *manual start attempt*; a timeline following MIDI timecode still does not start manually.

## 4. Changes per namespace

1. **`laser-show.animation.cue-chains`** (`animation/cue_chains.clj:1–27,59–75`): **NEW** `grid-content [cue]`, a pure projection of one cue map or `nil`. Return the four existing selector fields `{:timeline? boolean :preset-count n :first-preset-id id-or-nil :has-content? boolean}`. Define `:has-content?` **once**, as `timeline?` or a positive stored preset count. Move the walk at `subs.clj:273–281` here, following only group `:items`, never preset parameters or attached effects. Returning the label facts with the predicate lets the view use the same traversal. No new namespace or stored flag.
2. **`laser-show.subs`** (`subs.clj:1–19,35–37,269–291`): consume that projection from the cue read through the supplied context. Keep `cell-display-data`'s return shape, selection/active subscriptions and the picker's label projection (`subs.clj:2016–2025`).
3. **`laser-show.events.handlers.grid`** (`events/handlers/grid.clj:1–16,59–131,214–225`): make `handle-grid-trigger-cell` the sole ordinary-press transition. Read the cue from its `:state` co-effect; use the new projection's `:has-content?`. Route the existing `:grid/cell-clicked` key directly to this same handler as an input alias, ignoring any old boolean; delete the duplicate body. Apply the **same predicate** to the momentary press. Keep the guard at these grid entry points: `start-cue` is also called by the Vibe engine with its own eligibility and run ownership (`vibes/engine.clj:52–65`; `vibes/library.clj:193–214`).
4. **`laser-show.views.components.grid-cell`** (`views/components/grid_cell.clj:103–135,153–187,377–389`): make the cue wrapper supply `:grid/trigger-cell`; the generic single-click branch adds only `:col` and `:row` to the supplied command. Keep the existing double-click and secondary-button branches, and the rendered bit for styling, menu choice and drag initiation (`views/components/grid_cell.clj:38–52,158–173,180–187,325–353`). This generic callback also serves the Effects tab and Vibes picker: keep their own event types and payload fields; their handlers already read current data rather than the click's flag (`views/components/grid_cell.clj:535–545`; `views/components/vibe_picker.clj:72–87,100–106,118–124`; `events/handlers/effects.clj:29–50`; `events/handlers/vibes.clj:150–165,241–242`).

## 6. Events and effects

| Existing event | Dispatcher → handling decision |
|---|---|
| `:grid/trigger-cell` (canonical); `:grid/cell-clicked` (old spelling) | Single primary click (`views/components/grid_cell.clj:174–178,384`) or non-momentary input press (`events/handlers/triggers.clj:128–141`) → `events/handlers.clj:31–45` → `events/handlers/grid.clj:214–225`. Always select. Empty: return with playback unchanged. Otherwise `:default` global mode uses the cue's mode (missing → `:toggle`); any non-default global mode overrides it. `:toggle` with an existing intent removes it, toggle without one starts it; `:retrigger` starts a new run even when active (`events/handlers/grid.clj:19–33,63–79`). | `:grid/activate-cell` / `:grid/release-cell` | Momentary edges (`events/handlers/triggers.clj:65–79,128–130`) → same grid router → `events/handlers/grid.clj:81–93`. Press on content selects and attempts a fresh start regardless of trigger mode; empty press leaves selection **and** playback alone. Release removes an existing intent even if content has since disappeared; absent intent is a no-op. Release never selects or pulses. Ordinary key-up emits no grid command (`events/handlers/triggers.clj:132–155`). |

The grid handlers return only `{:state …}`. The external router's existing `:dispatch` carries `:source-input` and `:source-trigger` (`events/handlers/triggers.clj:178–185`); retain them, including history's source-trigger skip (`events/handlers/history.clj:280–312`). Current co-effect, state-first commit and inline follow-up are already wired in `events/core.clj:96–104,165–178,655–679,719–720`; the running app uses the single event executor (`app.clj:95–112`). The pulse is a state increment, not a separate effect. No new registered effect or device I/O.

## 7. Five cases to pin

Let `A = [2 1]`, `P = {:type :preset :preset-id :circle}`, and `r1`, `r2` be distinct run UUIDs. Compare playback to the state **immediately before the grid command**, not before the intervening edit. In rows 2 and 5 the pulse count starts at zero.

| Input at A, in handling order | Expected result |
|---|---|
| Render `{:items [P]}` → Clear A → deliver retained click | `selected = A`; cue still missing; playback identical to post-Clear, no new intent or pulse. Another cell's playing or held intent survives. |
| Render empty → fill `{:items [{:type :group :enabled? false :items [P]}]}` → deliver click twice; default modes and no other intents | Count `1`, first `:circle`. First press selects A, sets `{:run r1}`, `:active-cell` A, `:playing? true`, pulse `1`. Second removes A; `:active-cell nil`, `:playing? false`, still pulse `1`. |
| Store `{:name "Draft" :items [{:type :group :items []}]}`; selection was `[0 0]` | Content false, despite the map and nonempty top-level vector. Ordinary click or bound ordinary press: select A only. Momentary press from the same initial state: still `[0 0]`. |
| A already has run `r1`; `{:editor-type :timeline :items [] :trigger-mode :toggle}`; global `:retrigger` → press | Count `0` **and** content true. Replace with `{:run r2 :timeline? true :start-beat 0.0}`; pulse +1. Tracks alone can infer the same timeline. With `:timeline/chase :mtc` and no active intent, a press selects A but creates no manual run or pulse. |
| `{:items [P]}`, mode `:toggle` → momentary press twice → edit to `{:items []}` with the second intent still present → release twice | Presses produce `r1`, then `r2`, pulse `2`. First release removes A even though the predicate is now false; second does nothing. Pulse stays `2`. If Clear already removed the intent, the first release also does nothing. |

**Invariants:** the same address and current state give the same ordinary decision from either source, modulo fresh run IDs. Only a successful start/restart increments the cue pulse. Selecting an empty cell cannot start, stop or resume anything. Grid content is structural; it does not promise a rendered frame.

- **No prerequisite repair.** Land the shared cue rule and switch its consumers together, before [35, grid subscription fan-out](00-overview.md#L74) narrows these selectors ([merge order](00-overview.md#L88)). Neither defines cue-grid content. The clipboard's items/tracks test (`state/clipboard.clj:112–123`) and Vibe eligibility (`vibes/library.clj:193–214`) also serve different commands. This repair changes no renderer, output traversal or input-device lifecycle.
