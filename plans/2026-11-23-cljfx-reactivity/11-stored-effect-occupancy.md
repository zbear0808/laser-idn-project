## 1. Current behaviour

Put a zone pattern inside a disabled group in an otherwise unused effects grid. The editor still has the pattern, but its cell looks empty, offers **New zone pattern**, and cannot start a drag. Choosing the offered command does **nothing**: the writer already protects the group. The Grid and Perform tabs can also hide the pattern controls. ## 2. Root cause and decision

**Use one structural rule for authoring: an addressed effects cell is occupied if its saved `:items` contains a node.** A group is a node, even when it has no children: “New empty group” is an actual undoable edit (`views/components/list.clj:167–175,577–583`; `events/handlers/list.clj:342–363`). A missing cell and a cell with no items left are empty for directed creation and dragging; a name or an on/off switch alone is not an item. Within an occupied tree, the **inventory of effects** is its effect leaves in document order, including leaves disabled by themselves or by an ancestor. A group contributes no effect ID. This lets the UI say “occupied; zero effects” without offering to overwrite someone's group.

**Playable** answers a different question. A leaf must survive the enabled-only walk, and its cell must be on, before it can participate in its point, pattern or cycle stage (`animation/effects.clj:310–318`; `services/frame_service.clj:112–143`; `routing/zone_patterns.clj:241–256`). The cell switch is an arm/disarm control, not a report that an effect ran (`events/handlers/effects.clj:29–50`).

## 4. Changes per namespace

1. `laser-show.animation.chains` (`animation/chains.clj:1–16`): **NEW** `stored-effect-content [items]` returns **NEW projection** `{:has-content? boolean :leaves [effect-map …]}`. `:has-content?` is the authoring rule above. Descend only through a group's `:items`; emit the original non-group maps with a non-nil `:effect-id`, once per occurrence, irrespective of enablement, collapse, registration or cell activation. Do not search parameter maps. One pure reader serves both cljfx and handlers; no namespace or second persisted representation is needed.
2. `laser-show.subs` (`subs.clj:1–19`): **NEW** `stored-effect-cell [context col row]` subscribes to that coordinate's `:items` and applies the reader. This shares the inventory between the cell display and its rich tooltip without passing the context or a whole cell tree through child props. In `effect-cell-display-data` (`subs.clj:337–373`), `:effect-count`, `:first-effect-id`, `:effect-ids`, `:has-effects?` and `:display-text` describe the stored leaves; add **NEW in this result** `:has-content?` for occupancy (already the generic cell's input, `views/components/grid_cell.clj:103–119`). Keep `:active?` and `:selected?` separate. Forward the structural bit in `vibe-pick-fx-label` instead of substituting leaf count (`subs.clj:2027–2036`).
3. In the two aggregate subscriptions, use the **same reader** on saved items. `holds-effect?` matches a kind among stored leaves; keep the cue-pattern and independent zone-use branches (`subs.clj:1192–1217`). `effects-grid-empty?` (`subs.clj:375–383`) ignores a cell **only for the hint** if it has zero stored effect leaves, or **exactly one stored leaf and** `master-only?` is true. The cardinality check counts disabled siblings. A switched-off cell still qualifies if it contains only the functioning Master; disabling the Master leaf or its ancestor makes it an ordinary stored effect for the hint. No name or coordinate test. Keep `master-at`'s enabled-leaf contract (`test/laser_show/vibes/faders_test.clj:53–61`).
4. `laser-show.views.components.grid-cell` (`views/components/grid_cell.clj:1–8,475–509,535–548`): supply the structural bit to the generic cell and both **New** menus. Read stored leaves from the new per-cell subscription in `effect-lines` (`views/components/grid_cell.clj:444–458`), including the existing pattern/cycle descriptions. An unnamed, occupied tree with no leaves gets **NEW label** “Groups only”; the count is still zero. The Vibes picker reuses that label (`views/components/vibe_picker.clj:72–88,108–124`). Finish subscription reads during rendering as in `docs/CLJFX_STATE_MANAGEMENT.md:5–13`.
5. `laser-show.events.handlers.effects`, `.zone-patterns` and `.vibes` (`events/handlers/effects.clj:79–107`; `events/handlers/zone_patterns.clj:48–64`; `events/handlers/vibes.clj:156–165`): use the structural bit on the **current** addressed items for explicit creation, the drag **source**, and the effect branch of picker membership. Preserve the picker's ability to remove an existing membership even after its content was deleted. See §6 for the accepted and rejected actions.

## 7. Five cases to pin

Each row is the **only** effects cell, with no cue pattern or other zone use. `P` is the Chase cell pattern (`routing/zone_patterns.clj:128–137`), `S` is `{:effect-id :scale}`, and `M` is the real starter Master (`vibes/faders.clj:56–62`). The table lists effect kinds (`:effect-id`) in order; “playable” means passing the cell/ancestor/item gates. “New / drag” means the two directed creation menus / permission to start a move.

| Cell data | Stored / playable kinds | Occupied | New / drag | Pattern / map pads | Fresh-grid hint |
|---|---|---|---|---|---|
| `nil` or `{:name "Old" :items []}` | `[] / []` | no | yes / no | no / no | yes |
| `{:items [{:type :group :items []}]}` | `[] / []` | **yes** | no / yes | no / no | yes: no effect yet |
| `{:active? true :items [{:effect-id :zone-map-cycle :enabled? false}]}` | `[:zone-map-cycle] / []` | yes | no / yes | no / **yes**, CYCLE dim | no |
| `{:active? true :items [{:type :group :items [{:type :group :enabled? false :items [P S]}]}]}` | `[:zone-pattern :scale] / []` | yes | no / yes | **yes / yes** | no |
| `M` at `[0 3]` | `[:intensity] / [:intensity]` | **yes** | no / yes | no / no | **yes** |

**Invariants:** Disabling a leaf/group or switching off a cell cannot change which effects it stores, their order, or the pads' structural visibility. Removing the last pattern/cycle *can* hide the corresponding rows. Switching off `M` changes playability, not the hint; appending `{:effect-id :scale :enabled? false}` to `M` leaves the playable list alone but **removes** the hint. Copying or moving a Master does not turn its new cell into an available slot.

## 9. Boundaries

- **Automatic placement is intentionally stricter than directed creation.** `first-empty-effect-cell` reserves every non-nil entry, including a named shell; it searches unallocated coordinates bottom-up for a reaction, Master or Morph (`vibes/reactions.clj:173–203`; `vibes/faders.clj:117–139`). Keep that reservation: automatic placement must not silently repurpose someone's named slot. Its empty-map/full-grid fixtures are explicit in `test/laser_show/vibes/reactions_test.clj:124–131`. Likewise `apply-starter-effects` seeds a new project with an empty **map**; Open does not reseed it (`state/templates.clj:98–111`; `state/persistent.clj:244–255,257–271`). Neither operation consults the onboarding hint.
- Keep CYCLE on/running/paused, actual reactions, fader wiring and audience eligibility on their existing enabled-only paths (`routing/zone_maps.clj:78–88,165–178`; `vibes/reactions.clj:213–223,254–261`; `vibes/faders.clj:142–157`; `vibes/library.clj:148–152,173–191`). This is a document/UI interpretation change; the stored-content reader has no caller in frame processing. The separate undo issue concerning **live** Vibe ownership after a move is tracked in `plans/2026-11-23-cljfx-reactivity-audit.md:82`.
