## 1. Current behaviour

**A custom group used only in a cue's zone pattern can make Perform hide two different indicators.** I checked a populated HIT pool containing just `[0 0]`: its preset targets an untagged projector, but its enabled pattern includes a custom group assigned to a crowd-tagged projector. HIT also has a named, non-routing reaction. Here are the results on the same data, with just the vibe's permission varied. This was a fresh headless cljfx context with in-memory records; no pad press, app start or output was needed.

| Allow audience | Full-state audience cue? / playable cells | Perform today: `AUDIENCE` / `:effects-only?` | Cue picker `:blocked` | Expected Perform |
|---|---|---|---|---|
| `false` | `true` / `[]` | `false` / **`false`** | `:crowd` | `false` / **`true`** (“Effects only”) |
| `true` | `true` / `[[0 0]]` | **`false`** / `false` | `nil` | **`true`** / `false` |

- **Perform:** `vibe-pad-audience?` considers the **playing** vibe, only HIT/ACCENT pools and the single FLASH cue, and only cues the role may start (`subs.clj:1673–1682,2200–2217`). Separately, `vibe-reactions` puts a role in `:quiet` when it has no playable cue; `vibe-pad-reactions` exposes `:effects-only?` only when the role is quiet **and** has reaction names. `vibe-pad` supplies that data to the pad (`subs.clj:1807–1832,1834–1854`). `pad` sets both visibility and layout participation of the `AUDIENCE` label; `now-text` chooses “Effects only” (`views/components/vibe_pads.clj:38–49,56–65,114–131`). The header's `AUDIENCE ALLOWED` is a permission indicator, independent of any cell's reach (`views/tabs/perform.clj:97–105,126–131`).
- **Vibes picker:** `vibe-cell-blocked` keeps only `:timecode` or `:crowd` from the reason for the **edited** vibe; an empty cell has no blocked label. `vibe-pick-cell` and `vibe-pick-fx` carry that cue/FX-specific result to the picker (`subs.clj:1947–1961,1975–2001`; `views/components/vibe_picker.clj:23–24,58–63,90–106,108–124`). “audience” here means *excluded by this vibe*, not *allowed to play*.
- **Eligibility already works on the full state.** `press-pool` passes it to `library/playable-cells`; `press-flash` uses the same cue gate through `playable` and a separate `library/playable-fx` gate for effects (`vibes/engine.clj:130–132,303–318,418–435`; `vibes/library.clj:173–214`). The discrepancy above is a UI defect, not evidence of changed routing or actual emission.

## 2. Root cause

The two Perform selectors both use `reaction-inputs` (`subs.clj:1798–1805,1813–1823,2212–2217`). It carries the projectors **and their membership lists** but drops the top-level **group definitions**. Those are independent data: `[:projectors id :zone-groups]` says which custom groups an output belongs to; `[:zone-groups group-id]` says the group exists (`state/domains.clj:337–348,392–407`). A tagged output's membership puts the group in `library/audience-groups` (`vibes/library.clj:77–100`; `routing/rig.clj:65–77,479–492,517–532`). For a pattern, `library/audience-cue?` also calls `zone-patterns/reach`; the lane drops unknown refs, and `rig/known-ref?` tests the **definition** for a custom group (`vibes/library.clj:119–144`; `routing/zone_patterns.clj:276–291`; `routing/zone_remap.clj:122–137`; `routing/rig.clj:137–143`). Thus a cue aimed **directly** at `:crowd` passes the existing badge test (`T/subs_test.clj:639–655`), but the projected pattern loses its only audience destination even on the very first render.

The picker already reads the definitions in `vibe-audience-routing`. It also passes **separately** computed `vibe-audience-groups`, which includes virtual projectors (`subs.clj:1914–1921,1934–1954,1984–1994`). Simply giving today's picker routing map to `library/playable-cells` would lose *virtual* membership: that function recomputes audience groups from its state when the vibe disallows the audience (`vibes/library.clj:82–100,204–214`). Adding one more key to Perform's duplicate list would leave the same opportunity for drift.

## 3. What to reuse: the routing inputs and their readers

| Input to the shared projection | Why it matters |
|---|---|
| `:projectors`, `:virtual-projectors`, `:rig` (`subs.clj:1914–1921`) | Tags, membership, exclusion, physical IDs, enabled state and effective rig order determine the audience refs. A virtual output counts if it **or its parent** is tagged. Automatic refs follow the rig; a disabled physical scanner still contributes its stored refs and own laser ref (`vibes/library.clj:77–100`; `routing/rig.clj:221–246,269–288,479–492,517–532`). |
| `:zone-groups` (`subs.clj:1943–1945`) | Known custom IDs in an enabled pattern's destination lane. Reach uses the whole lane, including the expansion of `:lane/lasers`; neither `:from` nor the currently lit step decides reach (`routing/zone_patterns.clj:276–291`; `routing/zone_remap.clj:122–137`). |
| `:zone-maps`, `[:grid :column-targets]`, `[:config :default-target]` (`subs.clj:1934–1945`) | Content targets inherit through items/tracks/groups, cue, its column, the show, then All. A zone can reach an audience ref through **any** built-in or saved map, including an override, irrespective of `[:zone-map :active]` (`routing/targets.clj:106–118,133–162,305–322`; `routing/zone_maps.clj:24–57,90–104`; `vibes/library.clj:102–117`). |
| **Separate, addressed inputs:** current or edited vibe, role/slot and cell | `library/current-id` and `library/edited-id` have different selectors/owners and both fall back to the first vibe. `library/slot-cells` already returns a vector for each pool or a zero/one-element vector for a single cue (`vibes/library.clj:43–59,219–245,252–257`; `subs.clj:1673–1682,1870–1889`). `cue-cell-chain` and `effect-cell-chain` subscribe to one coordinate (`subs.clj:197–201,331–335`). Keep chains, vibe selection and reaction names out of the routing projection. |

## 4. Changes per namespace

Production changes belong in `laser-show.subs` (`subs.clj:1–26`). The library continues to decide reach and eligibility; the views continue to render their existing fields.

1. **One routing projection.** Move the existing `vibe-audience-routing` and `vibe-audience-groups` (`subs.clj:1914–1921,1934–1945`) ahead of their first Perform consumer. Extract **NEW private** `audience-rig-inputs [context]` for the three lookups in the first row of §3. The groups selector applies `library/audience-groups` to this slice; the routing selector extends the **same** slice with definitions, maps and the two nested defaults. This includes `:virtual-projectors` in the state-shaped routing value while group-set-only consumers need not follow map/default edits. Use cheap `fx/sub-val` leaves, compose with `fx/sub-ctx`, and finish reads in the supplied context (`subs.clj:4–16`; `docs/CLJFX_STATE_MANAGEMENT.md:5–12`). The audience calculation needs no active map, beat, backend status, label text or runtime snapshot.
2. **One result per cue-playing pad.** Add **NEW private** `vibe-pad-cue-status [context role]` → **NEW derived result** `{:quiet? boolean :audience? boolean}`. Read the current vibe by ID. Use `library/slot-cells` on the matching slot for HIT/ACCENT, and on `:flash-cue` for FLASH (`vibes/library.clj:232–245`). Extend the shared routing value locally at `[:chains :cue-chains]` with **only** those cells, eagerly read through `cue-cell-chain`. Pass this value, the vibe and the role cells to the unchanged `library/playable-cells`. Quiet means its result is empty. When permission is on, call `library/audience-cell?` with the shared group set **only on the playable result**; the badge is true if any matches (`vibes/library.clj:140–144,193–214`). Read the shared group set before walking this vector. For VIBE/BLACKOUT return both flags false. An unset FLASH cue or absent current vibe leaves a cue role quiet and unmarked. `vibe-pad-audience?` returns the badge field; `vibe-pad-reactions` uses the quiet field.
3. **Keep reaction names independent of routing.** Retire `reaction-inputs` (`subs.clj:1798–1805`). Narrow private `vibe-reactions` (`subs.clj:1807–1823`) to the existing `reactions/reactions` result by role. Supply the current entry at `[:config :vibes :library id]`, the cue chains named by its cue slots, and the effects grid: the name calculation includes the vibe's FX, its flash FX **and other active effects-grid cells** (`vibes/reactions.clj:270–308`). Return no names without a current vibe. Do not filter this list by cue playability. Replace the private quiet-set lookup in `vibe-pad-reactions` with the per-role result; keep `:reactions` and `:effects-only?` as today (`subs.clj:1825–1832,1853–1854`).
4. **Keep the picker cell-local.** `cell-blocked` still passes the edited vibe's permission (nil groups if allowed) to `library/unplayable` with the addressed cue; `fx-blocked` attaches only its addressed effect chain and calls `library/audience-fx?` (`subs.clj:1947–1961,1984–2001`). Both use §4.1. A pattern or Map cycle **in an FX cell** can mark the FX picker but does not, by itself, put a cue-start badge on FLASH (`vibes/library.clj:148–191`; `subs.clj:2206–2217`).

## 7. Data examples and invariants

Fixture fragment (existing fields from §§1–3; test IDs). The scanner is excluded from All, and the cue explicitly targets the other projector. The custom group is therefore the **only** audience path. Construct the pattern with `preset-instance :alternate :cue` (`routing/zone_patterns.clj:128–137`) and replace its lane:

```edn
{:rig {:order [:main :aud]}
 :projectors {:main {:enabled? true}
              :aud {:enabled? false :exclude-from-all? true
                    :tags #{:crowd-scanning} :zone-groups [:balcony]}}
 :zone-groups {:balcony {:name "Balcony"}}
 :chains {:cue-chains {[0 0] {:target :auto.laser/main
                              :items [{:type :preset :preset-id :circle}]
                              :zone-patterns [{:effect-id :zone-pattern :enabled? true
                                               :params {:style :alternate :zones [:auto.laser/main :balcony]}}]}}}}
```

For the table, current = edited, HIT names `[[0 0]]` unless stated, and its vibe has the separate “Energy size” reaction (`reaction-cell :energy-size`, `vibes/reactions.clj:57–61,89–90,158–171,263–266`). The last column is the expected **display** `[pad-mark quiet? effects-only? cue-picker-blocked-at-[0 0]]`.

| Fixture change | Allow | Full-state playable HIT cells | Expected display |
|---|---|---|---|
| Custom-group pattern as above | `false` | `[]` | `[false true true :crowd]` |
| Same group, same pool | `true` | `[[0 0]]` | `[true false false nil]` |
| Disable the cue's pattern (only `:enabled? false`) | `true` | `[[0 0]]` | `[false false false nil]` |
| Add a non-audience cue `[1 0]` to HIT after `[0 0]` | `false` | `[[1 0]]` | `[false false false :crowd]` |
| Keep the group pattern and populated cue, set `{:editor-type :timeline :timeline/chase :mtc}` | `true` | `[]` | `[false true true :timecode]` |

**Oracle for every case:** obtain the expected playable vector from `library/playable-cells` on the **full** immutable state. Quiet iff that vector is empty for a cue role; mark iff permission is on and `library/audience-cell?` on the full state is true for a cell **in that vector**. Effects-only also requires nonempty names. For the edited vibe, compare the cue picker with full-state `library/unplayable` retaining only `:crowd`/`:timecode` (`:empty` displays nil); compare the FX picker with permission off **and** full-state `library/audience-fx?`. Empty takes precedence over timecode, timecode over crowd (`vibes/library.clj:173–214`; `timeline/playback.clj:53–56`). These are not three equal booleans. Changing only which vibe is edited may change the picker but must not change the playing pad. Neither indicator claims which cue a shuffle will choose or what a device sent.
