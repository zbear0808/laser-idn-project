## 1. Current behaviour

**Verified in the audit's mounted headless app:** with Show Lock on and an enabled projector, clicking its **On** checkbox produced a refusal notice. After event delivery and rendering the database still said **on** and the actual checkbox said **off**. This is a false indication of the configured output, not a measurement of what a laser emitted. The audit distinguishes this check from the saved state-outcome script ([audit:63,106](../2026-11-23-cljfx-reactivity-audit.md#L63)).

The card reads its enabled value through `subs/rig-cards` (`subs.clj:1393-1419`; mounted at `views/components/rig_strip.clj:555-565,592-600`). ## 2. Root cause and UX decision

JavaFX changes the control first. The application's descriptions before and after refusal both say `:selected true`. A changed notice can repaint the status bar without cljfx setting that equal checkbox property a second time. Even the Vibes boxes' keys solve a *different* problem: they change when the edited vibe changes, not when the same vibe refuses a click (`views/tabs/vibes.clj:236-243,315-324`; [pinned cljfx: no controlled props](https://github.com/cljfx/cljfx/blob/1.10.6/README.md#no-controlled-props)).

**Decision: keep otherwise available controls interactive; dispatch the attempted edit once and explicitly restore the applied value.** A locked click gets the existing explanation and leaves a truthful control, as the driver inspector already does. Apply this same rule to the source-traced native inputs above. A control already unavailable for its own reason remains unavailable. No lock policy moves into the widget.

Turning a *card* off is currently a structural edit and is refused. Transport Stop, Stream off and BLACKOUT remain available (`views/toolbar.clj:57,299`; `events/show_lock.clj:9-21,53-57`; `T/events/show_lock_test.clj:206-246`). So do Fit guard settings and safety edits that only restrict the allowed area, including adding a blocked area or copying a smaller zone (`views/tabs/projectors.clj:340-383`; `events/handlers/projector.clj:505-519,730-743,760-780`; `T/events/show_lock_test.clj:316-352`). Likewise, Add Manual's live inputs edit a **draft**; only Add submits the blocked `:projectors/add-manual` intent (`views/dialogs/add_projector_manual.clj:110-136,146-159`; `events/show_lock.clj:48-51`).

## 4. Changes per namespace

1. **NEW** `laser-show.views.components.applied-value` (`views/components/applied_value.clj`): one `applied-control` adapter taking the native description, **logical address**, rendered value, native property getter/setter and user-change event translation. This is the driver mechanism shared by unrelated views, not a second guard. Migrate its two existing callers in `laser-show.views.components.driver-fields` (`views/components/driver_fields.clj:56-92`). Keep the 300 ms settling convention for a value still showing a pending edit; restart one FX timer per instance on a newer attempt. A timer is **not an acknowledgment**: an accepted value rendered later still wins.
2. Store the current address and applied value as declarative instance data (extend the existing `:user-data {:value …}` convention, `views/components/driver_fields.clj:73-80,87-92`). On settle, correct only the same live binding, only if it still displays that attempt and differs from the **latest** applied value. Rebind from model data on address change; stop the old timer and remove its listener on disposal. Guard the programmatic setter so it cannot dispatch, toggle membership, start another settle, or issue another notice. Do not suppress a real second user change merely because it equals the value from an earlier render. No callbacks reading an old bound context; see [reactive state rules](../../docs/CLJFX_STATE_MANAGEMENT.md#reactive-state-in-this-app), lines 7–13.
3. Adopt at the dispatchers in §1: `rig_strip.clj` (On), `tabs/projectors.clj` (tags, exclusion and live Name), `group_matrix.clj` (combo/slider), `tabs/vibes.clj` (both boxes, commit field for Name), `tabs/zones.clj` (physical/virtual member boxes). Preserve each widget's input contract: actual selected boolean, inverted for All; group **toggle** exactly once per user click, whether on the box or on the surrounding row; a slider sends its numeric changes and Name still edits per keystroke. A live text field settles after typing pauses, not after every character; focus loss after a settled commit must not resend it.
4. At `target_control.clj`, `zone_maps_panel.clj`, `zone_map_pads.clj`, `pattern_pads.clj` and `zone_pattern_editor.clj` (dispatchers in §1), reconcile the native check, radio or selected value; use the menu **item** as owner for a check-menu-item, not its ephemeral popup skin. In shared parameter controls, wire the adapter at the relevant native leaves for the addressed pattern editor, including Numeric mode and keyframe settings. Keep the existing data parsers and event templates. [06 owns the non-dispatching keyframe listeners](06-keyframe-control-dispatch.md) and [01 owns numeric Enter](01-numeric-commits.md); merely returning a map is not evidence of a refusal. Do not wrap labels, action buttons, the whole inspector, or the Perform surface.
