## 1. Current behaviour

Close the Step Grid while painting, then rename a cue. The paint can still own the Undo transaction: the rename gets no step of its own, and background beats can keep that transaction open ([audit observations](../2026-11-23-cljfx-reactivity-audit.md#L72-L81)).

- The grid pane sends `:step-grid/pointer` on press, drag and release (`views/components/step_grid.clj:129-159`). On the event thread `handle-pointer` translates the native event into `:step-grid/paint-start`, `:step-grid/paint` or `:step-grid/paint-end`. Even moving one pixel within the same cell returns `{:state state}` (`events/handlers/step_grid.clj:202-238`): no new paint, but still a `:state` effect and context swap (`events/core.clj:165-178`; `state/core.clj:148-172`).
- Press takes a baseline with `:source-id [:step-grid target]`, paints, and sets `[:ui :step-grid :drag]` to `{:target … :on? … :at …}`. Moves interpolate from `:at`. Release ignores its target and commits **whatever transaction is open** if there is a grid drag (`events/handlers/step_grid.clj:240-285`). The footer and window close both send `:ui/close-dialog` (`views/dialogs/step_grid_editor.clj:45-50,98-118`; `views/dialogs/common.clj:141-146`); its handler just sets the editor's `:open?` false (`events/handlers/ui.clj:44-50,196`). The root then omits the window (`views/root.clj:233-242,287-290`). There is a creation hook for focus, but no blur/disposal finish. The audit's **close** probe found both the drag and the transaction still open; the missing focus/disposal paths are code-traced.
- History tests for identical document **roots**, then touches an open transaction, and only *after* that branch asks whether undoable content changed (`events/handlers/history.clj:272-324`). `:show-clock/status` writes `[:timing :beat-index]` (`services/show_clock.clj:186-203,300-305`; `events/handlers/timing.clj:203-209`; `animation/show_time.clj:68-75`). `:timing` is a document root, but its projection contains only BPM and even BPM is live for Undo (`state/history.clj:57-84,192-206`). The audit reports **125 simulated seconds** of beats keeping an abandoned transaction open; a subsequent edit acquired no separate step. Today's 60,000 ms check is opportunistic, before non-history events only, and only substitutes the incoming state; a following handler with no `:state` effect need not publish that closure (`state/history.clj:43-46,473-487`; `events/handlers/history.clj:255-263,281-298`).
- This is a shared contract. Both slider constructors begin/end with reusable parameter keys; their value events carry no press identity (`views/components/parameter_controls.clj:92-104`; `views/components/modulator_param_control.clj:109-121`). The interactive canvas has a node ID, labels the phase of its callbacks, and dispatches begin/commit/abort (`views/components/visual_editors/canvas_interaction.clj:22-34,202-213,238-252,255-285,317-331`). The history handlers ignore even `:source-id` on commit/abort (`events/handlers/history.clj:20-47`); a second begin from the same source keeps the previous baseline (`state/history.clj:432-471`).
- **Baseline change:** `7b320b3` made `:modulator/toggle` a **discrete**, single-state edit of keyframe mode and modulation (`views/components/modulator_param_control.clj:434-438,472-481`; `events/handlers/modulator.clj:32-51`). Its immediate Undo/Redo fixture (`T/events/history_handlers_test.clj:363-386`) supplies a real foreign edit for this plan.

## 2. Root cause and decision

A press has no identity of its own. The UI and history each remember part of it, and history treats **an open baseline** as permission to group **every** edit. Neither a changed root, an event type, nor “same control” proves membership. A close-only fix leaves the next untagged edit vulnerable; a timeout-only fix still permits an old release to finish a new drag.

Keep one whole-document transaction. **Only a change to undoable content from the matching press extends it.** Commit the accepted paint on release, loss of focus, disposal or expiry. An actual unrelated undoable edit interrupts the gesture: seal it against the document **before** the unrelated edit, then record that edit normally. Further moves from the interrupted press are ignored until the next press. Thus beats and UI updates never cut a continuous drag into steps, and a real intervening edit can be undone independently in chronological order.
