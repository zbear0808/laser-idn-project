**Supersedes / Superseded by:** the *provider-as-thumbnail-source* decision only in `plans/2026-11-19-zones/05-phase-z3-routing-core.md:135–140`; none supersedes this page. **Related findings:** [redraw gate and attempted frame](../2026-11-23-cljfx-reactivity-audit.md) at lines 73 and 90; `plans/2026-11-07-improvement-review/04-output-pipeline.md:138–143` (local sends vs link health).

Paths without another prefix are relative to `src/laser_show/`. **NEW** marks proposed names. The evidence boundary is the **sanitized frame argument of the last driver send call that returned normally**. The driver returns statistics or `nil`, not a picture, a receipt from the device, or evidence of light.

## 1. Current behaviour (file:line)

1. **The producer records an attempt.** `services/show_clock.clj:258–304` takes the tick's state/input snapshots, renders, then publishes. `backend/multi_engine.clj:208–244` composes, applies the fit guard, calibration and safety; `guard-safety` returns `[]` on error (`backend/multi_engine.clj:133–149`). `create-projector-frame-provider` checks tick age, smooths the fit record and calls `show-time/record-output!` **before returning** the frame; on a caught error it records `nil` (`backend/multi_engine.clj:246–287`). `animation/show_time.clj:368–383,401–413` stores even `nil` as a fresh `{:frame nil :at-ns …}` in a process-wide map by projector ID, cleared on clock runtime reset.
2. **The consumer of that frame may do something else.** `create-engine-for-projector` wires the provider into the driver engine (`backend/multi_engine.clj:293–320`). In `streaming-loop` (`backend/streaming_engine.clj:386–418`), a not-ready tick can be skipped *before* calling the provider. Otherwise `nil` becomes an empty vector (`animation/types.clj:141–144`), and `sanitize-frame` drops invalid points, enforces the dark first point and minimum non-empty length (`idn/frame_rules.clj:19–31`). Only then does `send-frame!` call the driver; a normal return, including `nil`, has the existing stats semantics (`backend/streaming_engine.clj:217–233,259–265`). A throw can lead to an independent `[]` recovery call, which can itself return or throw. Stop and a dead session requesting reopen skip that recovery; the recovery return updates the local pacing timestamp, not the regular send/fit stats (`backend/streaming_engine.clj:420–448`). Neither outcome reaches the thumbnail. Even the built-in driver can encode fewer samples than the input and returns local transfer counts (`idn/driver.clj:123–136,189–219`).
3. **The painter is gated by a different clock.** The card supplies ID, limit and size (`views/components/rig_strip.clj:37–39,275–313`). `output-thumbnail` requests `:every-ms 100`, but `start-timer!` calls its painter only on a change in `[tick tick-stale? user-data]` (`views/components/preview.clj:219–231`; `views/components/clock_view.clj:28–56`). `redraw-thumbnail!` ignores the tick, reads `output-frame` and checks **provider** age `< 250 ms`; a recent timestamp alone gives the accessible text “Laser output”, even for `nil`. Its inner drawing key uses `System/identityHashCode` of the points plus freshness, limit and canvas size (`views/components/preview.clj:184–217`; threshold `animation/show_time.clj:345–348`). Meanwhile the visible “Not streaming” label tests whether the slow status is `:streaming`, so even an error or a start can get that label (`views/components/rig_strip.clj:275–302`).

## 2. Root cause

The provider cannot observe what the driver was passed or whether it returned. The clock cannot announce an output change that happens **after its last tick**. For example, freeze tick 7 at 0 ms; its provider records a frame at 150 ms. At an FX sample at 300 ms the *tick* is stale but the *frame record* is fresh. At 400 ms the record expires; the tick, its stale flag and the props still have exactly their 300 ms values. The old gate never asks the painter again, even for a subsequent recovery. Moving the timestamp to the driver return fixes only the first defect. `show-clock/stop!` stops ticking (`services/show_clock.clj:353–363`); engines can still pace themselves or resend the same tick as a keepalive (`backend/streaming_engine.clj:84–89,333–355`). A clock stop is not an output-session end. These are source traces, not device measurements.

## 7. Data examples and invariants

Five scripted inputs. Times below are **monotonic ms** for readability; store ns. `A` and `B` denote distinct synthetic frame vectors; no driver sends bytes.

| Input → observation | Required display / invariant |

| `A` returned at 10; `B` throws at 20; recovery `[]` held until 30 | While held: **Unknown**, A's timestamp still 10, no points. If recovery returns: `{:frame [] :at-ns 30000000 :source :recovery}` → **Empty (retry)**. If it throws: **Unknown**, no new success time. | Tick 7 at 0, `A` returned at 150, no later ticks or prop changes; FX samples at `[200 300 400 500]`; successful `[]` recovery at 480 | Captions `["Driver frame" "Driver frame" "Stale" "Empty (retry)"]`. | Repeated not-ready ticks or a blocked send after `A` → same `:last-ok`; then a successful keepalive of the same vector | Only the return renews freshness. | Session `[:r1 :s1]` holds `B`; stop/drain, replace same projector ID with `[:r2 :s2]`, `A` returns there, then release old success/failure/cleanup | Between owners no inherited frame; the new session starts unknown, then shows `A`.
