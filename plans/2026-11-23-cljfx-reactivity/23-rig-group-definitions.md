# 23 — Restore the group definition with its last rig member

**Status:** Proposed · **Last verified against:** `7b320b3` (2026-11-23; in-memory event pipeline).  
**Supersedes / Superseded by:** none · **Related findings:** [audit: half-restored identities](../2026-11-23-cljfx-reactivity-audit.md#L82); [zones ZR, as built](../2026-11-19-zones/09-phase-zr-rig-file.md#L423-L426). Source citations below are relative to `src/laser_show/`; `T/` means `test/laser_show/`.

## 1. Current behaviour

**Reproduced:** A saved show did not define `:group-balcony`. Its one disabled projector `:p` listed that ID; the local rig copy held `{:id :group-balcony :name "Balcony" :description "House" :color "#2468AC"}`. I passed each event and the preceding result's state to `handle-event-pipeline` (`events/core.clj:628–653`), with streaming off and a non-nil writable path. The write requests below were inspected, not executed.

| Event | `:p` membership | Local definition | Requested `rig.edn` definition | `[undo-depth redo-depth]` |
|---|---|---|---|---|
| Initial | `[:group-balcony]` | House | — | `[0 0]` |
| `{:event/type :projectors/remove :projector-id :p}` | projector gone | absent | seq 1: absent | `[1 0]` |
| `{:event/type :edit/undo}` | `[:group-balcony]` | **absent** | seq 2: **absent** | `[0 1]` |
| `{:event/type :edit/redo}` | projector gone | absent | seq 3: absent | `[1 0]` |

The show stayed clean throughout. From the **undone** state I also tried New and Open independently. New kept `:p` but omitted Balcony from the new show's groups. Opening a different show without that ID kept `:p`, but the rig report's `:rig-groups-not-in-show` was `[]`; the same report on the initial state included Balcony. Both operations cleared both stacks. These consumers use the effective rig copy (`state/persistent.clj:232–271`; `state/rig_file.clj:328–351,415–425`). **Decision:** keep the missing definition with the snapshot that can bring its membership back. Restore it to the rig copy in the same event; the open show's definitions stay under show ownership.

## 2. Root cause

- `listed-groups` gathers custom IDs from **both** physical and virtual outputs, including disabled ones. `group-copy` takes definitions from `[:rig-file :group-copy]`, overrides them by ID with the show's `[:zone-groups]`, and keeps only listed IDs. `rig-document` puts that map at `:zone-groups` in the **rig file** (`state/rig_file.clj:26–64`; `routing/rig.clj:59–70`). Dropping an unlisted definition from the next file is correct.
- The membership edit takes a **pre-edit** snapshot (`events/handlers/history.clj:272–324`). Its `:document-state` contains the projectors, virtual projectors and **show** definitions, but no rig-only definitions (`state/history.clj:57–84,369–375`). Outside history and dirty tracking, `write-request` immediately replaces the only in-memory rig copy with the filtered one, before any writer acknowledgement (`events/core.clj:645–653`; `events/handlers/rig_autosave.clj:21–46`). Undo puts back the ID, then autosave materializes the new file from two maps that both lack its definition. Waiting for or flushing the writer cannot fix the snapshot.
- The problem is also observable **without removing the projector**. Creating a show group named “Balcony” may reuse the rig-only ID: `unique-group-id` checks the show, not the rig (`events/handlers/zone_groups.clj:47–76`). In a second pipeline check the new definition had description `"Show"`. Undo removed it from the show but left `"Show"` in the writable rig copy instead of restoring `"House"`. With a read-only or nil path the write middleware did not update the in-memory copy at all (`events/handlers/rig_autosave.clj:15–19,40–46`). File permissions should govern I/O, not which definition can be recovered locally.

## 4. Changes per namespace

1. **`laser-show.state.rig-file`** (`state/rig_file.clj:1,38–77`): give `group-copy` a **NEW arity** `[state fallback-definitions]` to project a specific snapshot's definitions against *that state's* physical/virtual memberships and show definitions. The existing one-argument form supplies the live rig copy. Extend `rig-changed?` so a change to the **copy field itself** can trigger comparison of the two *effective* copies, just as a change to the show definitions does now. The criterion remains a value difference in the four rig paths or in the effective copy, not a change to the whole rig-file status map.
2. **`laser-show.state.history`** (`state/history.clj:1,62–84,295–315,369–375`): add **NEW** `:rig-only-group-definitions` as a field **beside** `:document-state` on every snapshot. Capture `group-copy` of the state being snapshotted minus the IDs defined in that state's show. Keep each complete definition map, indexed by ID; record `{}` when empty. Compute it at snapshot creation, **not** in `extract-document-state` used by dirty comparisons and the saved baseline. Add **NEW** pure `restore-snapshot [state snapshot]`: first use `restore-document`, then compute `group-copy` on that restored state with the snapshot field as its fallback. Of the rig-file session fields, replace only `[:rig-file :group-copy]`, keeping the current value when equal. A present `{}` is authoritative; for an older in-memory snapshot *lacking* the field, use the current rig copy as best effort. Never infer an unknown definition from an ID, a same-named group or a backup file.
3. **`laser-show.events.handlers.history`** (`events/handlers/history.clj:1,38–47,75–125`): use `restore-snapshot` in **both** `apply-restore` (Undo and Redo) and `handle-abort-transaction`. Return the paired result in one state. The existing pre-confirmation check still sees a candidate; a refused/unaccepted Undo must not install its definitions, consume a stack entry or request a rig write. No special case in individual projector handlers.
4. **`laser-show.events.handlers.rig-autosave`** (`events/handlers/rig_autosave.clj:1,15–46`): separate remembering the active definitions from requesting I/O. In `wrap-rig-autosave`, if the handler returned state and any rig path, show group map or **copy field** changed identity, bring the local copy to `group-copy` of that candidate, including when read-only or no path. Preserve the existing map when equal. Compare old and final rig content with `rig-changed?`. Only a writable, changed rig gets the normal numbered write. `write-request` builds the immutable document and increments the live request count; remove its responsibility for retaining the copy. Keep an explicit Retry as one request, not an additional automatic write. Update the field's “as last written or read” description in **`laser-show.state.domains`** (`state/domains.clj:1,579–598`): this is the window's current copy, not an acknowledgement.
5. **`laser-show.state.persistent`** (`state/persistent.clj:1,193–209,232–271`): in `apply-loaded-project`, take the outgoing effective rig copy **before** replacing the show. After migration, use it as fallback for `group-copy` of the loaded state; install the result in the rig copy before marking clean. This works even with a supplied state whose outgoing show has the only definition. Open does **not** merge that copy into the incoming show's definitions. New already seeds the starter show's defaults with the outgoing **listed** groups before clearing history/marking clean. Keep that rule. Startup already reads the rig file into the copy and joins it to the starter show (`state/rig_file.clj:456–472`; `app.clj:152–176`). No new namespace or file format.

## 7. Data examples and invariants

Let `g = :group-balcony`, `A = {:id :group-balcony :name "Balcony" :description "House" :color "#2468AC"}` and `B` have the same ID/name, description `"Show"`, color `"#CC4400"`. A snapshot before removal has this **projection** (not an on-disk shape):

```edn
{:document-state {:projectors {:p {:zone-groups [:group-balcony]}} :zone-groups {}}
 :rig-only-group-definitions {:group-balcony {:id :group-balcony :name "Balcony" :description "House" :color "#2468AC"}}}
```

| Input → operation | Required output |
|---|---|
| 1. One `:p` lists `[g]`, show `{}`, fallback `{g A}` → Remove / Undo / Redo / Undo, writable | Rig-file `[seq, :zone-groups]` = `[1 {}]`, `[2 {g A}]`, `[3 {}]`, `[4 {g A}]`. `:p` is present only on the restored side. Show `{}` and clean throughout; no explicit Save required. |
| 2. `:p` and a virtual output both list `g` → remove membership from `:p`, then remove the virtual output's parent | First copy `{g A}` (still listed), then `{}`. Undo the second edit → virtual membership and `{g A}` return together; aborting a transaction containing that same removal has the same restore result. |
| 3. One member, show `{}`, copy `{g A}` → create show group `g` with `B` / Undo / Redo | `[show, effective rig copy, show dirty?]` = `[{g B} {g B} true]` → `[{} {g A} false]` → `[{g B} {g B} true]`. Different IDs named “Balcony” stay distinct. Read-only and nil-path runs have these same local results and **zero** rig requests. |
| 4. Fork after Undo in row 1 → New; separately New after Redo | First: defaults plus `{g A}` in the **new show**. Second: defaults only. Both start clean with empty history; unused groups from the previous show/stack do not seed New. |
| 5. After Undo, Open a ZIP with foreign rig paths and no Balcony group; separately Open one defining `g` as `B` | First: local member + `{g A}`, incoming show has no `g`, report includes `{:group-id g :name "Balcony" :lasers 1}`; no rig write for unchanged payload. This is report **data**; that informational row alone does not open the dialog (`state/rig_file.clj:357–361`; `events/handlers/menu.clj:124–135`). Second: local member + `{g B}`, incoming definition wins, writable rig gets one update. Both keep this machine's four rig paths and clear the old history. |

**Invariant:** At each capture/restore, use membership IDs, never group names or “enabled” counts. The active copy contains exactly the *known* definitions for listed custom IDs; `:all`, `:auto/*` and `:auto.laser/*` are derived (`routing/rig.clj:59–70`). A pre-existing unknown ID stays unknown; it is not silently deleted or given invented metadata. Rig-only edits preserve any pre-existing dirty show edit. New/Open cannot undo back into the outgoing show (`state/persistent.clj:193–209`; `events/handlers/history.clj:132–146`). Intermediate rig documents may be coalesced; each emitted document must be consistent on its own.

## 9. Scope and alternatives considered

A permanent dictionary of deleted groups would let old definitions survive history eviction and ID reuse. Putting the rig copy into the show's `:zone-groups` would silently change the open show, its report, Save and dirty semantics. A per-snapshot fallback has the same lifetime as the membership it can restore. ZR already established one history and separate file ownership; [the original deletion/retargeting finding](../2026-11-07-improvement-review/02-events-state.md#L124-L131) is a different operation. Coordinate the shared restore call with [pages 14 and 22](00-overview.md#L87-L90); they own projector selection and vibe ownership. The writer lifecycle and pattern reference traversal have [separate owners](00-overview.md#L53-L62).
