# 24 — Give each input Learn attempt one owner

**Status:** Proposed · **Last verified against:** `7b320b3801b8` (source and fixtures, 2026-11-23).  
**Supersedes / Superseded by:** none · **Related findings:** [Settings Learn](../2026-11-23-cljfx-reactivity-audit.md#L67), [old-show completion](../2026-11-23-cljfx-reactivity-audit.md#L79), [Learn All and cell behavior](../2026-11-23-cljfx-reactivity-audit.md#L88); [earlier input review F9–F11](../2026-11-07-improvement-review/05-input-triggers.md#L85-L107). Source paths are relative to `src/laser_show/`; `T/` means `test/laser_show/`.

## 1. Current behaviour

- **Settings has two listeners but no completion handler.** The MIDI and OSC cards dispatch separate Start/Cancel events and show “Waiting for … input” (`views/components/midi_settings.clj:88–96,178–202`; `views/components/osc_settings.clj:80–87,157–182`). Each Start stores a promise under its device's `:learn-mode`; the callback delivers the first routed event of that source and unregisters itself (`events/handlers/input.clj:99–123,193–217`). `subs/midi-learning?` and `subs/osc-learning?` test whether the promise is present, not whether a result was published (`subs.clj:1528–1532,1564–1568`). The audit observed **realized promise, absent listener, still waiting**. Neither card supplies a binding target.
- **Document binding already goes through history.** Generic Start releases `!pending-learn`, creates a promise, registers `::generalized-input-learn`, records `:learning-target` and `:learning-capture`, and returns `:input/await-learn` (`events/handlers/input.clj:231–247,285–316`). Its registered effect dispatches `:input/learn-captured` from a future (`events/core.clj:313–322,719–724`). The current defect is not the old review's direct future write or undeclared promise effect. Press and fader callbacks **deliver, then unregister the shared key** (`events/handlers/input.clj:269–283,297–306`). Completion can already have started the next wizard listener; the audit gated the old callback and left ACCENT waiting with no listener.
- **The target is not the attempt.** `learn-target` retains only `:type/:target/:role/:slot`; both completion branches compare it with the current target (`events/handlers/input.clj:239–247,361–374,403–415`). Cancel/restart for the *same* cell or slider therefore accepts the first capture. In the editor, the enabled combo changes existing bindings and the dialog choice, but the callback carries the **original** `:target-action`, behavior included (`views/components/trigger_bank.clj:107–118,151–163,171–189`; `events/handlers/input.clj:314–316,380–392,444–467`). Choosing While held after starting on Follow can bind Follow. These choices actually play differently (`events/handlers/triggers.clj:65–79,128–141`).
- **New/Open and stop have different lifetimes.** Successful replacement resets dialogs and Vibes UI but preserves backend input, including the pending target (`state/persistent.clj:193–222,243–255,257–271`). The audit delivered an old capture and found a binding, Undo entry and dirty flag in the new show. App stop removes the mapper and stops input sources, but does not retire a learn listener/waiter (`app.clj:308–340`; `events/handlers/input_mapper.clj:116–125`). Unregister alone cannot recall a callback: the router traverses a snapshot (`input/router.clj:103–128`).

## 2. Root cause and UI decision

Three places claim to be waiting (two device promises and a generic target), and none identifies *which request* may write or remove a listener. Use one active attempt across Settings, editor, grid, pads, faders and Learn All. **NEW `:learn-id` identifies one attempt, including one wizard step or retry.** A document binding also belongs to the particular open show: consume [20's document identity](20-document-completions.md), **NEW** `[:project :document-id]` → `:document-id`, as agreed in the [ownership contract](00-overview.md#three-ownership-decisions-that-span-pages).

**Settings identifies one input.** Label the buttons **Identify MIDI input** / **Identify OSC input**. Show **Cancel** and the waiting prompt while listening. The first normalized message of the requested source restores the button and shows what was detected on that card. This is a passive check: existing input routing continues, and the check creates no mapping. Enable Start only for enabled MIDI with a connected input, or enabled OSC with a listening server (current status fields: `state/domains.clj:529–543`). **The cell behavior choice stays editable.** The pending binding uses the last choice accepted for that cell; the selector shows that same choice. A change need not restart Learn or require another press.

## 4. Changes per namespace

1. **`events/handlers/input.clj:99–123,193–217,231–247,285–316,351–425,473–516`** becomes the sole Learn state machine. Add **NEW** pure `begin-learn [state request fresh-id]` and `end-learn [state identity]` for all entry/exit paths. Dispatch the existing vibe Start/Cancel through these same transitions (`events/handlers/vibes.clj:191–202,246–247`). Put the wizard queue in its active attempt. On an accepted step, commit the binding and the next active attempt together; on refusal, keep the queue, set the refused role, and allocate a fresh attempt for the same step. A manual Start supersedes the wizard even if it targets the very same role. No deferred, unqualified “start next” or “cancel current” event.
2. **`events/core.clj:93–109,313–322,628–679,719–724`**: inject **NEW** `:fresh-learn-id` (UUID) in a learn-only wrapper on Starts, Learn All and captures that can begin another step. Keep it distinct from the incoming `:learn-id`; a cached description, clock tick or timestamp must not supply identity. Add **NEW** pure `wrap-learn-lifetime [handler]` in `events/handlers/input.clj`, alongside the before/after middleware in the pipeline (§3). It ends an invalidated owner (§6) and emits a single listener change only if the active ID changes. Run `:state`, then that change, then any inline follow-up; ordering must not depend on map iteration. A behavior edit with the same ID leaves the listener, its deadline and its fader baselines intact.
3. **`input/router.clj:37–44,63–84,103–128`**: add one optional **NEW** `:learn-listener` in the existing runtime router atom, identified by `:learn-id`. **NEW** `replace-learn-listener! [expected-id next-listener]` exchanges that slot only if its owner matches (`nil` means empty); it never clears other handlers. Offer an incoming event to the slot in the *same router snapshot* before ordinary listeners. Mark discrete presses during a binding attempt `:learn-only?` for the mapper, even if completion runs before the mapper receives that press. A Settings probe does not set the marker. Keep the existing keyboard marker and pass releases and continuous writes through (`views/key_triggers.clj:35–61`; `events/handlers/input_mapper.clj:59–66,85–112`). Remove the mapper's second, racy test of global learn state.
4. **NEW `laser-show.input.learn`** (`input/learn.clj`), runtime adapter shared by the registered effect and app teardown: `sync! [change dispatch]` arms/retires just the specified slot. Move the catcher out of the state handler. Reuse the promise/waiter mechanism from `events/core.clj:313–322`, but make the promise private to this attempt and bound the previously indefinite wait to **30 seconds per attempt**. Only this adapter constructs the callback, promise, waiter and fader baselines. A callback can deliver to *its own* promise once; neither the callback nor the waiter ever unregisters a listener. The waiter dispatches one capture or timeout with its original identity; retirement wakes a waiting promise with cancellation. A capture already queued still has to pass the handler's checks. Remove the two device promise APIs/defaults (`input/midi.clj:246–272,294–303`; `input/osc.clj:262–288,315–323`; `state/domains.clj:529–543`).
5. **UI and model.** Declare the plain session data in `state/domains.clj:153–160,193–199,217–218`. Replace all direct old-path reads with projections from §5. In `views/components/trigger_bank.clj:94–118,151–189` and `views/dialogs/cell_trigger_editor.clj:13–23,48–54`, send cell identity on Start; resolve the current displayed behavior in the handler. The choice event validates Follow/While held, current document and open editor cell, updates existing matching bindings, dialog choice and matching pending action **in one returned state** (`events/handlers/input.clj:444–467`; today's follow-up merges arbitrary dialog data at `events/handlers/ui.clj:52–73`). When pending, the combo prefers that action's behavior; when idle retain the existing interpretation of legacy bindings as Follow. Grid-menu starts keep their cell address and normal Follow default.

## 6. Events, effects and teardown order

All app events below use the existing domain router (`events/handlers.clj:41–45,61–68,75–77`); their handlers return data. A **document-bound** Start must name the document from which it was dispatched: reject a missing or non-current `:document-id` before superseding anything. For capture, timeout and Cancel, require a non-nil matching `:learn-id`; for a binding, also require **event document = active document = current document**, all non-nil. Check before clearing UI, changing a binding, advancing the wizard, emitting a notice or touching a listener. Missing or stale identity yields `{}`. Get the action from current state, never from the result payload.

**Which input qualifies:** Settings accepts any routed message from its selected source, including releases. A press Learn accepts `:note-on` or `:trigger`, never a release. An explicit `:continuous` request or a `:macro` target waits for travel (§3). Nonqualifying input leaves the listener armed. On a current completion, validate source/lookup key again; for a fader the offered `:store-key` must be among the normalized event's actual `store-keys` (`events/handlers/input.clj:318–326,403–415`). A malformed result from a claimed attempt retires it as failed, without binding or advancing.

**When a surface or show goes away:** on leaving Settings cancel its probe; on MIDI becoming disabled/losing the last connected input or OSC stopping, cancel **only** that source's probe. Use the published status (#25), not a device close hook. Today the tab changes at `views/root.clj:95–104` → `events/handlers/ui.clj:15–18` and the device controls dispatch at `views/components/midi_settings.clj:53–56,115–121,212–217` / `views/components/osc_settings.clj:131–142`. On editor close or retarget, retire only the editor-owned attempt for the old cell (Close and window X: `views/dialogs/cell_trigger_editor.clj:62–67,81–87`; `views/dialogs/common.clj:141–146`; retarget: `views/components/grid_cell.clj:369–376,524–530`; handlers: `events/handlers/ui.clj:30–50`). A standalone pad/grid Learn or Learn All survives a tab switch and ends by capture, explicit cancel, replacement or deadline.

On **committed** New/Open, reset the whole Learn UI in `state/persistent.clj:193–210` alongside #20's identity change; the before/after wrapper retires the *old* ID in that turn. New/Open menu dispatch is `views/components/title_bar.clj:65–73`; chooser/load continuation is `events/handlers/menu.clj:71–107,114–141` via `events/core.clj:201–209`. A cancelled chooser, failed Open, Save, or Undo is not a document replacement. At app stop, retire the outgoing runtime slot and wake its waiter during [#19's serialized app retirement](19-app-and-scan-generations.md), before handing input to the next app. Use the same retire-only operation, idempotently, without dispatching a bare Cancel to the next app or waiting for the event thread from itself (`app.clj:325–340,345–351,381–396`). A queued completion uses the effect's owning dispatcher, never the global synchronous fallback after stop (`events/core.clj:111–117,811–835`).
