**Units and keys.** Controller IDs are zero-based Jamepad indices. The four stick keys are `:left-x`, `:left-y`, `:right-x`, `:right-y`; the two triggers are `:trigger-left`, `:trigger-right`. `normalize-axis` maps stick `−1..1` to `0..1` (centre `0.5`) and leaves trigger `0..1` alone (rest `0.0`). Missing previous axes currently compare against **`0.5` for all six**. Thus a centred new stick is quiet and a resting new trigger emits `0.0`. The comparison is strict `abs(delta) > 0.005` in normalized units (`input/gamepad.clj:29–47,73–76,88–99`). The event carries `:channel` = controller, `:control` = axis and a clamped double `:value`; the store holds **one vector key** `[:gamepad controller axis]` → double. Only the label adds one to the controller number, and only the meter text multiplies a level by 100 (`input/events.clj:17–29`; `events/handlers/input_mapper.clj:30–57,85–92`; `input/store.clj:7–30`; `views/components/trigger_bank.clj:72–82`; `views/components/slider_meters.clj:17–33`).

**Sampling and defaults.** `tick!` reads the raw physical-key map even without a playing cue. Today, `render-context` adds `[:macro slot]` from the current `[:config :input :macro-map]` for the render; the clock independently derives the snapshot's `:faders` from the same read (`services/show_clock.clj:115–143,267–299`; `services/frame_service.clj:159–194`). `fader-values` returns `{slot level}` for *seen, currently bound* sources; `with-faders` removes stale keys for both slots before adding the current ones. `0.0` is a value; missing is not zero. The macro's `:default` is a **normalized fader position**, used before scaling into the parameter's `:min..:max` (`vibes/faders.clj:21–48`; `animation/modulator_evaluators.clj:257–266`). Cycle Offset is in **steps**, not beats, percent or a map ID. The default cycle is Left / Right then Odd / Even; rate `0.25` means one step per four beats (`routing/zone_patterns.clj:99–108,139–143,258–271`; `routing/zone_remap.clj:59–78`).

## 2. Root cause

1. **The axis threshold forgets unpublished motion.** A button edge needs the last observed button state. An axis needs its displacement from the last value *emitted for that axis*. Comparing adjacent samples loses a slow sweep; it can also publish alternating noise across the two sides of a stationary value. The existing threshold test covers one small move and one large move, not a series of polls (`T/input/gamepad_test.clj:36–42`).
2. **The derived inputs are available too late for the cycle.** The clock must choose the map **before** building routing, hence before cue rendering. `cycle-step` constructs a global timing context with `:pulses` only; `effects/resolve-effect-params` uses that context and `modulation/make-context` defaults omitted `:input-values` to `{}` (`services/show_clock.clj:245–251,275–289`; `animation/effects.clj:216–229,440–445,530–551`; `animation/modulation.clj:43–74`). Passing the raw store alone would fix a direct MIDI/OSC modulator but still miss a learned fader. Reading the previous published tick would lag both movement and binding changes by a tick.

## 4. Changes per namespace

1. **`laser-show.input.gamepad`** (`input/gamepad.clj:1–10,53–82,101–123`): add private, pure **NEW** `next-poll-baseline [prev sample emitted]`. Return the existing controller-map shape: only controllers still present, each with the sampled `:buttons` and its retained `:axes` entries for still-present axes. For each emitted control change put its `:value` at `[channel :axes control]`; leave subthreshold axes at their previous publication (missing means the existing `0.5` reference). This helper advances memory without re-diffing or timestamping a second event. In `poll-loop`, read once per enabled pass, diff against that baseline once, dispatch the vector once and recur with the advanced baseline after successful dispatch. Keep the disabled empty sample, retry with the old baseline on the existing error path, and interrupt/stop handling. Clarify `prev` in the diff docstring. No new atom.
2. **`laser-show.vibes.faders`** (`vibes/faders.clj:1–10,21–48`): extract **NEW** `tick-inputs [raw macro-map]` → `{:faders levels :input-values enriched}`. Keep `with-faders [raw macro-map]` as the `:input-values` projection for existing callers. The pair is needed because the meter uses slot keys and the modulator uses vector keys; neither representation is the device store.
3. **`laser-show.services.frame-service`** (`services/frame_service.clj:1–13,146–194,471–476`): extract **NEW** `render-context-with-inputs [state input-values global-clock pulses zone-ctx]` from the existing render-context assembly. Its contract is **already enriched** input values, used unchanged for both `:input-values` and `[:global-ctx :input-values]`. Keep all current `render-context` arities accepting **raw** values: derive them with `with-faders` then delegate. This preserves out-of-clock rendering, including the two-argument `generate-frames-by-zone` fallback. Distinct entry points avoid guessing whether a map is prepared from the presence of a macro key (an unbound show has none).
4. **`laser-show.services.show-clock`** (`services/show_clock.clj:1–24,77–93,115–143,239–305`): at the existing state/store reads, prepare `tick-inputs` exactly once from those two immutable inputs. Pass its `:input-values` into `cycle-step` (one extra argument); associate it alongside `:pulses` on the global timing context. Preserve the existing BPM fallback and error boundary. Then resolve effective map → routing → zone context. Pass that **same enriched map** to `render` and the prepared frame-service entry point; publish the pair's `:faders`. Keep the empty-runs shortcut: the cycle and meter get this tick's inputs even when nothing renders. Each cue retains its own clock; the projector context gets the same inputs but no pulses. Do not construct a full render context early to get a fader: its zone context depends on the routing the cycle is about to choose.

**Invariants:** Displacement is absolute from one axis's last publication, not total path length or time spent moving. A quiet axis neither moves its own baseline nor prevents a button edge or another axis from emitting. One store read and one binding resolution per tick, including stopped ticks; later input belongs to the next tick. Keep raw physical keys, omit unseen slots, honour explicit zero, and apply each modulator's own fallback. `gamepad-poll` has a 16 ms enabled / 100 ms disabled sleep; `show-clock` targets 60 ticks/s (`input/gamepad.clj:37–41,101–111,169–175`; `services/show_clock.clj:68,316–331,342–351`). Read counts and numerical results are checkable; latency/FPS impact is **unverified**.

## 9. Scope

The publication threshold, connection bootstrap, learn threshold, map ordering and starter defaults are existing policies. This page changes when a physical axis emits and which inputs reach cycle evaluation. Learn attempt lifetime is [24](24-input-learning.md); ownership of a non-keyboard button's original action is [26](00-overview.md#finding-index); the editor's manual/effective map distinction is [29](29-effective-map-selection.md). No per-sample database events, timer, persistence migration or change to device/output lifecycle is needed.
