## 1. Current behaviour

- **Open already knows which unit is which.** The ZIP has `hardware.edn`, `content.edn` and `project-metadata.edn`; both cue and effect chains are show content, whereas projectors and calibration are rig-owned (`state/persistent.clj:41-45,68-86`). `apply-loaded-project` replaces the show, resets the session, normalizes timeline cues, runs the Z2 show rows, then Z4, then `rig-file/rename-pins`, **before** marking the result clean (`state/persistent.clj:193-222,232-255`). `pin-map` matches the archived and local projector IDs by settled identity; an unmatched unit keeps an unused ID or gets a free one if the ID is occupied. `rename-pins` turns *changed* ID pairs into `:auto.laser/<id>` pairs (`routing/rig.clj:48-57,644-666`; `state/rig_file.clj:81-123`).
- **The pin can be right on the cue and wrong in its pattern.** `refs/replace-refs` walks cue/item/group/clip/track targets, column/show defaults, preview cells/filter and custom map lanes/override **values**. Neither the cue's pattern vector nor an effects-grid chain is in that walk (`routing/refs.clj:79-120,148-152,171-220`). A matched unit with a new ID can therefore leave a pattern pointing nowhere, or at another unit using the old ID. The current portable test checks the cue, an item and a preview cell (`state/rig_file_test.clj:108-160`); the pattern persistence test reopens a cue with lettered zones and a Map cycle, with no pin to translate (`state/persistent_test.clj:630-646`).
- **The preview picker and map editor use different lists, both missing the same input.** `subs/zones-in-use` gathers `refs/cue-refs` plus column/show defaults, filters zones and sorts by letter index; `subs/map-zones` adds A/B (`subs.clj:1033-1056,1130-1134`). Preview uses **zones-in-use**, through `target-control/menu-context` and the `:preview` menu model: it also keeps the cell's own selection, but offers no “New zone” (`views/components/target_control.clj:34-42,66-73,95-104,186-195`; `views/components/preview.clj:317-355`). The map labels, Zones line and override choices use **map-zones** (`views/components/zone_maps_panel.clj:41-57,208-216,261-268`). A zone named only by a pattern can be absent from both.
- **Reports count owners, not occurrences.** `refs/cue-refs` includes `:all` for a cue with no own target; `cues-using` returns distinct cue coordinates, never effect cells (`routing/refs.clj:126-146`). The rig report derives both missing pins and groups without lasers from these cue refs/counts (`state/rig_file.clj:259-300,328-361`). Its render projection doesn't even include the effects grid (`views/dialogs/rig_report.clj:85-105`).

## 2. Root cause

The reference table predates the zone-pattern effect. These two features need the same answer: **which literal references does the document contain, and in which fields?** That is different from asking which places can receive a frame. The stage expands `:lane/lasers`, removes unknowns/repeats and intersects lit steps with the lane (`routing/zone_remap.clj:122-137,148-163,165-188`); `zone-patterns/reach` uses the whole lane and deliberately excludes the source `:from` (`routing/zone_patterns.clj:276-291`). An unknown pin, a disabled pattern, an unselected keyframe and a source-only zone all matter to document operations.

## 4. Changes per namespace (proposed order)

1. **`laser-show.routing.refs` (existing, `routing/refs.clj:1-31`).** Put the structural walk here, beside its existing consumers; no new namespace or registry.
   - **NEW private `pattern-ref-sites [items]`** describes occurrences relative to a chain root, e.g. `{:path [0 :items 1 :keyframe-modulator :keyframes 0 :params :steps 2 0] :role :lit :ref :auto.laser/old}` (**NEW** intermediate data). Roles: `:lane` for a direct keyword in `:zones`, `:source` for a keyword at `:from`, `:lit` for a direct keyword in a step. Traverse only existing parameter maps on `:zone-pattern` leaves. The stored format is vectors; read ordered EDN sequences in these slots as the existing readers do (`views/components/parameter_controls.clj:247-258`; `routing/zone_remap.clj:148-163`). Never descend into a map standing in for a value, a non-ref member, or an arbitrary `:items`/`:params` key elsewhere.
   - **NEW private `pattern-refs [items]`** enumerates the set of refs from those sites. **NEW private `map-pattern-refs [items replacements]`** rewrites those *same* sites. An absent replacement means keep the literal, a present `nil` means clear, an equal replacement is a no-op. Use exact keys, never name matching or a “known on this rig” filter. Keep occurrences until mapping is finished: a set suffices to ask “used?”, not to edit a particular step or keyframe. Look up the original values and rebuild touched containers together, keeping vector/list form and untouched branches; deleting an index must not shift the next edit. Mapping rules are in §7.
   - Extend `cue-refs` and `rewrite-cue` for `:zone-patterns`; add one **NEW** `:effect-chains` entry in `ref-places` for cell `:items` (`routing/refs.clj:126-152,171-220`). Do not register cue patterns twice. **NEW `chain-ref-usage [cue-chains effect-chains]`** returns `{ref {:cues #{[col row] …} :effect-cells #{[col row] …}}}` with sorted coordinate sets (both empty for an absent ref when looked up with defaults). Build cue entries from the extended `cue-refs`, effect entries from `pattern-refs`. This is a pure return value shared by the catalogue and reports; `cues-using` keeps its cue-only contract.
2. **`laser-show.subs` (existing, `subs.clj:1038-1056,1130-1134`).** Extend `zones-in-use` to take the keys of that usage map plus the column/show target refs, filter with `targets/zone-ref?` and return an eager, distinct vector sorted by `zone-index`. Retain the cue, column and `default-target` subscriptions. Add **NEW derived subscription `effect-ref-inputs [context]`**: read `[:chains :effect-chains]` and project the cells with items to `{cell {:items items}}`. Both catalogue and report need this structural input; a change only to cell `:active?` leaves it equal. Read it via `fx/sub-ctx`; don't traverse inside a `sub-val` extractor. A source-only, stored-step-only or keyframe-only zone is named even if nothing draws there now. Of the two selectors, only `map-zones` adds A/B. Map override keys, zone labels and a preview preference do not put a zone into the show's inventory.
3. **`laser-show.state.rig-file` and `laser-show.views.dialogs.rig-report` (existing, `state/rig_file.clj:113-123,259-300,328-361,427-436`; `views/dialogs/rig_report.clj:85-105,140-168`).** Keep `pin-map` and its callers; update `rename-pins`'s list of places (legacy Zone Selectors are converted on load). Build the owner index once per `match-report` and use it in place of cue-only `used-refs`/`cue-count` for the two warning sections. Keep `:cues` numeric, including zero; add **NEW optional report-row field `:effect-cells`**, the count of distinct effect cells, only when positive. A group still needs a show definition and no local member; a pin still needs to be absent on the local rig. One warning per ref, not per step. In `report`, augment the `report-inputs` projection at `[:chains :effect-chains]` with `effect-ref-inputs` so the dialog and its link (`views/components/rig_file_status.clj:61-64,83-87`) agree with the Open handler. Use “referenced by 1 effect cell” / “referenced by 2 cues and 1 effect cell”; a source reference doesn't mean a cue sends output to that laser. Existing repin buttons apply to all its stored sites.
4. **Existing remove/forget consumers.** In `events/handlers/zone_groups.clj:108-118,141-195,197-231`, `events/handlers/projector.clj:582-606,625-658` and `events/handlers/rig.clj:288-325`, count effect cells separately in the existing use message and offer the existing retarget choice even if an effect cell is the *only* owner. Keep cue-coordinate details cue-only. Use reference wording for the choice/notices (“Replace references with”, “Clear references”); on clear, describe the specific pattern-field rules below rather than promising every pattern inherits. Keep the existing map/column/membership treatment and one replacement per confirmed action. Use “Re-pin References” for the existing repin undo label (`events/handlers/history.clj:186-195`).
5. **Migration compatibility (existing, `state/migration.clj:95-110,123-151,153-186,199-206,220-231,266-307`).** No new archive format, version flag or second load pass. Z2's `show-rows` already calls `replace-refs` for a removed built-in judged against the *archived* rig; the extended walk handles modern pattern fields if present in mixed data. Keep `old-keys` and Z4's conversion/removal of old selectors in migration only. A show with no patterns acquires no pattern data. The later set-up/import buttons already remap from the IDs at Open to the IDs *now* via `renamed-since`; they must use the extended table exactly once (`state/rig_file.clj:190-199,228-244,366-377`).

## 7. Data examples and invariants

1. **A portable show.** Archive `:projectors {:a {:stable-id [:unit "AB CD" 1]}}`, local `:projectors {:a {:stable-id [:unit "EE 01" 1]} :b {:stable-id [:unit "AB CD" 1]}}` ⇒ replace `:auto.laser/a` with `:auto.laser/b`. Here are the relevant `content.edn` fields, with unrelated fields elided:

   ```edn
   {:chains
    {:cue-chains
     {[2 0] {:zone-patterns [{:effect-id :zone-pattern :enabled? false
                              :params {:style :steps :from :auto.laser/a
                                       :zones [:zone/c :auto.laser/a]
                                       :steps [[] [:zone/c :auto.laser/a]]}}]}}
     :effect-chains
     {[2 0] {:active? false
             :items [{:type :group :enabled? false
                      :items [{:effect-id :zone-pattern :params {:from :auto.laser/a}
                               :keyframe-modulator
                               {:enabled? false :keyframes [{:position 0.0 :params {:zones [:auto.laser/a]}}
                                                            {:position 1.0 :params {:steps [[:auto.laser/a] []]}}]}}]}]}}}}
   ```

   Result: cue source `:auto.laser/b`, rows `[:zone/c :auto.laser/b]`, steps `[[] [:zone/c :auto.laser/b]]`; cell source `:auto.laser/b`, keyframe params `{:zones [:auto.laser/b]}` and `{:steps [[:auto.laser/b] []]}`. The usage entry for that pin has `:cues #{[2 0]}` **and** `:effect-cells #{[2 0]}`. Neither enabling anything nor inspecting the current frame is necessary.
2. **Swap, don't chase.** For `{:auto.laser/a :auto.laser/b, :auto.laser/b :auto.laser/a}`, rows `[:auto.laser/a :auto.laser/b]`, steps `[[:auto.laser/b] [] [:auto.laser/a]]` ⇒ rows `[:auto.laser/b :auto.laser/a]`, steps `[[:auto.laser/a] [] [:auto.laser/b]]`. One lookup per *original* ref. Reopening the newly saved show on the same rig is stable because its archive now names that rig; applying a swap map twice is **not** idempotent.
3. **Merge or clear a ref, keep the rhythm.** `{:group-old :group-kept, :group-gone nil}` on `{:zones [:group-old :zone/c :group-kept :group-gone] :from :group-gone :steps [[:zone/c :group-kept] [:group-old :group-gone] [:group-gone] []]}` ⇒ `{:zones [:group-kept :zone/c] :steps [[:group-kept :zone/c] [:group-kept] [] []]}`. For a collision, keep the first surviving row position and the union of lights on the merged row, once per step in resulting row order. No shortened time axis, scalarized singleton, alphabetical sort or dangling row in a previously valid grid. Clearing an explicit `:from` removes the key (normal source default `:all`, **not** `:any`); clearing the last explicit row leaves `:zones []`, not an absent field that could reintroduce preset rows. An absent lane in a sparse snapshot is not an empty lane to filter its steps against: map/remove only the actual step refs there, retaining their order and unrelated values.
4. **No invented refs.** A pattern with `{:style :swap}` enumerates `#{}`; one with `{:zones [:lane/lasers] :from :any}` also has no literal target to translate. Keep those tokens verbatim. Explicit `{:from :all}` enumerates `#{:all}`; a missing `:from` never does. The legacy `cue-refs` fallback for the *cue* is read-only: mapping `:all` never inserts a missing cue target. The identical keyword in a style, pulse, modulator slot, instance ID, map-cycle map list, unrelated effect's params or vendor metadata is not a site. On empty/unmatched replacements keep the **identical** document, including missing/nil keys and unaffected siblings; never fill defaults, expand “Every laser” or sanitize a malformed subtree as a side effect. The supported tokens/defaults are in `routing/zone_patterns.clj:73-108`, `views/components/parameter_controls.clj:247-258,313-321`.
5. **Catalogue versus report.** No explicit cue/column/show target. A cue pattern has `{:from :zone/aa}`; an inactive effect cell has a base lane `[:zone/f :auto.laser/gone]` and a sparse keyframe `{:steps [[:zone/c] [:auto.laser/gone] []]}`. ⇒ `zones-in-use` and the preview zone rows with no current selection: `[:zone/c :zone/f :zone/aa]`; `map-zones`: `[:zone/a :zone/b :zone/c :zone/f :zone/aa]`. With archived `:gone` named “Balcony” absent locally, the missing-pin row is `{:ref :auto.laser/gone :name "Balcony" :cues 0 :effect-cells 1}`. It offers repin once; it does not claim a cue plays there.
