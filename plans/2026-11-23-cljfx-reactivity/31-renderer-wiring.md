# 31 — Wire dev validation into the app renderer

**Status:** Implemented in `db90de8` on `reactivity/integration` (2026-11-24); see [implementation status](00-overview.md#implementation-status-2026-11-24). Planned as: Proposed · **Last verified against:** `7b320b3` (2026-11-23, macOS arm64, JavaFX headless)

**Supersedes / Superseded by:** none · **Related findings:** [reactivity audit, renderer #1](../2026-11-23-cljfx-reactivity-audit.md#L30-L43); [previously deferred event-reentry finding](../2026-11-16-output-runtime/03-phase3-event-reentry.md#L176-L177); [improvement review F17, vendored dev help](../2026-11-07-improvement-review/06-testing-build-tooling.md#L225-L230).

**Decision:** Keep `fx/create-app`. Give it `:renderer-error-handler` in every mode and use its `:renderer-middleware` extension point to decorate the resolver **only in dev**. The application keeps the same context atom, renderer mount and asynchronous map-event handler.

App source paths are relative to `src/laser_show/`; `T/` is `test/laser_show/`; `deps.edn`, `build.clj`, `dev/`, `plans/`, `docs/` and `.github/` are at the repo root. **FX** means a path inside `cljfx/cljfx 1.10.6`; **Dev** means one inside `io.github.cljfx/dev 1.10.6.42`. Line numbers are from the installed jars ([FX `api.clj` at tag `1.10.6`](https://github.com/cljfx/cljfx/blob/1.10.6/src/cljfx/api.clj#L555-L614); [Dev `dev.clj` at the jar's SCM revision `9ea975a`](https://github.com/cljfx/dev/blob/9ea975ab9da8394363415f3dd128e5a7016f89d1/src/cljfx/dev.clj#L335-L363)).

## 1. Current behaviour

- The app pins FX in `deps.edn:12–16`. Only `:dev` supplies `dev/`, `-Dlaser-show.dev=true` and the Dev jar (`deps.edn:60–78`); `dev-config/dev-mode?` checks that property (`dev_config.clj:44–51`). The release build uses just the platform alias and copies `src` and `resources` (`build.clj:17–21,75–95`).
- `app/get-type->lifecycle` tries to resolve the default Dev resolver, logs the F12 message on success, uses it for keyword types only, and otherwise uses the standard context-aware lookup (`app.clj:60–85`). `app/create-app` passes the resulting function in `:opts` and `app/default-error-handler` as `:error-handler` (`app.clj:45–58,95–112`). **Neither option is read.** Rerunning the audit's capture of the actual nested `fx/create-renderer` call (`plans/probes/cljfx_reactivity_2026_11_23.clj:33–43`) gave `[custom-resolver? custom-renderer-error-handler?] = [false false]`; changing just the key to `:renderer-error-handler` gave `[false true]`. The separately nested `:async-agent-options :error-handler` **is** effective.
- Function views already receive a bound context. `fx/create-app` builds its own renderer opts and mounts once, returning `{:renderer R :handler H}` (FX `cljfx/api.clj:584–614`). Both normal startup and `app/start-test!` store that pair and register **H** for `events/dispatch!`; `app/stop!` unmounts **R** from the same atom and clears the dispatcher (`app.clj:234–240,325–340,389–398`; `state/core.clj:38–41,57–60`; `events/core.clj:796–802,811–835`).

## 2. Root cause and two dev-classpath prerequisites

1. **Wrong API boundary.** `:opts` and `:error-handler` belong to `create-renderer` (FX `cljfx/api.clj:401–432`). At the app boundary the keys are `:renderer-middleware` and `:renderer-error-handler`. FX supplies `:fx.opt/map-event-handler H`, and its resolver is keyword lookup followed by `fn->lifecycle-with-context` (FX `cljfx/api.clj:354–376,574–614`). Dev's prebuilt `type->lifecycle` defaults to plain `fn->lifecycle`; installing it for every type would lose subscriptions. Dev's **factory** `wrap-type->lifecycle` accepts `:type->lifecycle` as a keyword argument and defaults `:inspector-shortcut` to `[:f12]` (Dev `cljfx/dev.clj:64–74,337–363`).
2. **The dev namespace cannot load from the checkout today.** In a fresh dev JVM, resolving the factory fails with `Unmatched delimiter: )` at repository `dev/cljfx/dev/help.clj:165:35`. The Dev jar loads that resource *before* it defines the factory (Dev `cljfx/dev.clj:247,335–358`). Simply dropping the resource also failed on JavaFX `28-ea+11` (`deps.edn:107–114`): the jar's color help accesses a private `NAMED_COLORS` field via the first declared class; help is evaluated at load time (Dev `cljfx/dev/help.clj:140–166,515–519`). The local version, introduced by `de62bcc`, enumerates public `Color` fields instead (`dev/cljfx/dev/help.clj:140–165`). Keep that adaptation; fix its one unmatched closing delimiter.
3. **A validating renderer must mount the real starter Grid.** After correcting that reader error in memory, the real Dev wrapper rejected two valid shapes:
   - `{:fx/type fx/ext-many :desc [{:fx/type :stage :fx/key :main-window …}]}`, nested in `fx/ext-set-env` (`views/root.clj:250–269,284–290`): Dev reports `:fx/key - failed: unexpected prop`. Dev validates each child as a standalone `:cljfx/desc` before the list has consumed its key (Dev `cljfx/dev/extensions.clj:25–41`; `cljfx/dev.clj:87–100,177–201`). FX actually uses `:fx/key` for identity and strips it before forwarding the child (FX `cljfx/api.clj:237–245`; `cljfx/lifecycle.clj:319–337,345–367`).
   - `{:fx/type :menu-item :style-class ["menu-item" "target-menu-header"]}` and the audience class (`views/components/target_control.clj:137–146,157–165`): Dev reports `failed: string?` on the item and on its parent menu's items. FX supports the list (FX `cljfx/fx/menu_item.clj:10–23`; `cljfx/coerce.clj:508–509`); Dev incorrectly declares this particular prop `:string`, despite already having a `:cljfx/style-class` spec for a string or collection of strings (Dev `cljfx/dev/definitions.clj:235–238,864–877`).

## 3. Reuse / extend

| Existing boundary | Use here |
|---|---|
| App handler construction (FX `cljfx/api.clj:596–614`; `cljfx/event_handler.clj:8–13,22–49`; `cljfx/defaults.clj:29–41`) | Let FX inject co-effects, run effects and create the one agent per app. The app's `events/ordered-pipeline` commits `:state` first; its event co-effect `:fx/context` remains **nil**, not the render context (`app.clj:95–112`; `events/core.clj:655–679,719–721`). |
| `events/event-executor`, `events/on-event-thread?` (`events/core.clj:764–790`); `app/agent-error-handler` (`app.clj:87–93`) | Same shared single-thread executor (`laser-show-events`) across app instances, same two-argument agent callback. A render error instead goes to the one-argument `app/default-error-handler` on the FX application thread (FX `cljfx/renderer.clj:14–31,41–46`). |
| Public `cljfx.lifecycle/Lifecycle` protocol and `root` (FX `cljfx/lifecycle.clj:1–8,20–24,59–70`) | Renderer middleware takes **a lifecycle**, not an options map. FX composes `wrap-context-desc` (outermost), `wrap-map-desc` of the app's `:desc-fn`, then our middleware directly around `root` (FX `cljfx/api.clj:603–611`). It builds that chain once per renderer and delegates all three phases through it (FX `cljfx/renderer.clj:49–65,72–86`). |
| `wrap-context-desc`, `wrap-map-desc`, `fn->lifecycle-with-context` (FX `cljfx/api.clj:370–382,391–399,603–611`; `cljfx/lifecycle.clj:499–540`) | Keep FX's composition. On create/advance the context becomes a lifecycle option; the app's `:desc-fn` returns `{:fx/type root/root-view}`; each function component separately subscribes using its incoming description. On delete FX clears the context cache and does **not** inject a new `:fx/context`. |

## 4. Changes per namespace

1. **Dev load prerequisite:** in the existing `cljfx.dev` resource override (`dev/cljfx/dev/help.clj:1,157–165`), repair the delimiter and identify the upstream version and public-field adaptation in a comment. No fork of the validator or inspector.
2. **NEW `laser-show.dev-renderer`** in `dev/laser_show/dev_renderer.clj`. This keeps the Dev require and the two version-specific spec corrections off the production classpath. After requiring `cljfx.dev`, register **only** these replacement specs with public `clojure.spec.alpha/def` (spec.alpha `0.5.238`, `clojure/spec/alpha.clj:347–361,579–590,666–675`):
   - `:cljfx.ext-many/desc` (Dev `cljfx/dev/extensions.clj:37–41`): a collection of maps. For **validation only**, remove `:fx/key` from the immediate child copy, then validate it against `:cljfx/desc`. The actual description reaching FX, including every identity key, is untouched.
   - `:cljfx.composite.menu-item/style-class`: use Dev's `:cljfx/style-class`. The generated spec name follows from Dev `cljfx/dev.clj:186–201`; the source and target specs are in `cljfx/dev/definitions.clj:235–238,864–877`. Keep type checks on the individual classes and all other props. Pin positive **and negative** cases so a dependency upgrade can retire the corrections.
   - **NEW `middleware [delegate]`**, the dev-only entry point. Return a `reify` of `Lifecycle` delegating `create [this desc opts]`, `advance [this component desc opts]` and `delete [this component opts]`. Forward each call's description/component and return the delegate's result; change only `:fx.opt/type->lifecycle` in its incoming opts. Given the incoming base resolver **B**, derive **D** with `cljfx.dev/wrap-type->lifecycle` using `{:type->lifecycle B :inspector-shortcut [:f12]}` as keyword arguments. Memoize **B → D within this middleware instance**; Dev already memoizes per-type lifecycles inside D (Dev `cljfx/dev.clj:346–358`). Rebuilding D per call would give fresh lifecycle objects: FX tests their identity to advance vs. delete/recreate (FX `cljfx/lifecycle.clj:29–55`). D delegates keyword and function types to B; for an explicit lifecycle object Dev falls back to the type itself (Dev `cljfx/dev/validation.clj:403–445`).
3. **`laser-show.app`** (`app.clj:1–41,45–112`): replace `get-type->lifecycle` with **NEW private `get-renderer-middleware []`**. Off: return `identity` without resolving the optional namespace. On: `requiring-resolve` the **NEW** symbol `laser-show.dev-renderer/middleware` once at app setup. If the optional namespace/jar cannot be loaded, warn with the cause and use `identity` for this mount; handle a missing var explicitly. Keep that catch at **load time**: a bad description during rendering must reach the logger, not silently disable validation. Replace the current “tools active” message with a message about the middleware actually selected. Use the supported app options below. Do not change either startup caller or construct another app handler.

## 6. Events and effects

No new application event, registered effect or asynchronous completion. The existing map event `{:event/type :view/toggle-preview}` (`views/components/title_bar.clj:164–172`) is a useful check: the native listener calls **H** with `:fx/event` added (FX `cljfx/lifecycle.clj:152–162`); **H** queues on the shared executor, reads `:state` and `:time` (`events/core.clj:96–109,674–679`), and routes to the menu handler (`events/handlers.clj:63–70`; `events/handlers/menu.clj:344–349,463`). It returns the UI change as data; the registered `:state` effect commits it (`events/core.clj:165–173,719`). Imperative dispatch still uses the same **H**. F12 is Dev's scene event filter; reporting a render failure is the existing bootstrap logging callback, not an application effect.

## 7. Option examples and invariants

**Option data** (symbols denote function values; other existing app options are at `app.clj:103–112`):

```edn
;; At fx/create-app, dev loaded
{:renderer-error-handler app/default-error-handler
 :renderer-middleware    laser-show.dev-renderer/middleware
 :async-agent-options    {:fx/executor events/event-executor
                          :error-handler app/agent-error-handler}}

;; At the nested fx/create-renderer, *before* middleware runs, in BOTH modes
{:error-handler app/default-error-handler
 :middleware    composed-lifecycle-middleware
 :opts          {:fx.opt/map-event-handler H :fx.opt/type->lifecycle B}}
```

| Input | Expected observation |
|---|---|
| Production property unset; no Dev jar | Zero optional resolutions. Same B and H reach the root. F12 on the starter main window produces no inspector. |
| Dev requested, optional resource missing | One load warning; stock B, same H, same custom renderer logger. No “inspector active” claim. |
| Dev loaded, lifecycle advance with `{:fx/context C2 :fx.opt/map-event-handler H :fx.opt/type->lifecycle B}` | Delegate receives the identical C2 and H, and stable D in place of B. Delete preserves whatever opts FX supplies then; never retain C2 to add it back. |
| Stable test child subscribes to `:n` in `{:n "a" :other 0}`; change `:other`, then `:n` to `"b"` | Child calls after each render: `[1 1 2]`; label becomes `"b"`. The FX component instance survives the advance. No context prop on the child description. |
| Dev child now returns `{:fx/type :label :text 17}` | One throwable reaches the **renderer** error handler. Its message identifies `:label`, `:text` and the cljfx component stack (Dev `cljfx/dev/validation.clj:103–115,174–180,423–434`); zero agent errors. |

**Headless cross-check while planning:** With only the delimiter corrected in memory and the two spec registrations above, the pinned real `fx/create-app` with this middleware mounted the real starter Grid. Firing **Show Preview** ran on `events/on-event-thread?` with a nil event `:fx/context`; `[model-visible? panel-present?]` became `[false false]`. F12 produced `.inspector-root`. Create/advance/delete all received the identical returned H, the factory wrapped B once, and unmount left zero showing windows and zero recorded renderer errors. The separate two-function label fixture produced the call sequence and validation error above. These were isolated JVM probes with no services started, not a passing implementation or a suite run.
