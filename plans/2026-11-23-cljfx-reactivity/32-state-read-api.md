## 1. Current behaviour

`get-state` advertises memoized UI rendering, but calls `fx/sub-val` with `identity` on the **global root** it just dereferenced. `get-in-state` reads a path from that whole-map result. Neither accepts the component's context (`state/core.clj:63–82,174–185`). **Rechecked in a fresh JVM, without mounting the app:** warm two selectors on the same root, one using `get-in-state`, the other reading BPM from its supplied context. Replace `{:timing {:bpm 120.0}}` with `{:timing {:bpm 142.0}}`. The cached selectors returned **`[120.0 142.0]`**; a direct `get-in-state` call *after* replacement returned **`142.0`**. This is a missing render dependency, not a stale read at invocation. The [audit probe](../probes/cljfx_reactivity_2026_11_23.clj#L23-L31) gives the two selector shapes.

A changed library layout could yield a silent `nil`; a watch comparing two missing values could falsely report no changes.

## 2. Root cause

In pinned cljfx, a function component is evaluated as a subscription and receives its own bound context ([`lifecycle.clj:525–540`](https://github.com/cljfx/cljfx/blob/1.10.6/src/cljfx/lifecycle.clj#L525-L540)). Dependencies are collected on **that argument** while the function runs. A read on the root can populate the root's cache without registering anything on the enclosing component; an entry with no recorded inputs can be reused in the next generation ([`context.clj:80–98,106–138`](https://github.com/cljfx/cljfx/blob/1.10.6/src/cljfx/context.clj#L80-L138)). Eager realization or being on the FX thread doesn't turn a global read into a subscription. The assertion about leaking a **bound** context concerns its lifetime ([`context.clj:68–78`](https://github.com/cljfx/cljfx/blob/1.10.6/src/cljfx/context.clj#L68-L78)); it is not a prohibition on every off-thread read.

The public read interfaces are subscriptions; upstream explicitly calls the context a black box ([`api.clj:450–492`](https://github.com/cljfx/cljfx/blob/1.10.6/src/cljfx/api.clj#L450-L492)). This version stores the exact input map under its internal key at creation and replacement ([`context.clj:140–156`](https://github.com/cljfx/cljfx/blob/1.10.6/src/cljfx/context.clj#L140-L156)). The app needs a **no-subscription, no-cache** read for consumers that already know *when* to sample; the key is a pinned compatibility exception, not public cljfx API.

## 4. Changes per namespace (proposed)

1. **One representation adapter.** In `laser-show.state.core` (`state/core.clj:1–22,84–96,162–172`) add **NEW** `root-context->snapshot [root-context]`: a read-only conversion for a root obtained from the app atom, an atomic swap, or a watch. It takes **the supplied root**, never dereferences the global, never subscribes, and returns the actual map without copying it. `nil` root → `nil`; non-nil root without the expected map → explicit compatibility error naming the adapter and the pin, not an empty/uninitialized state. This is the only `:cljfx.context/m` lookup in source or tests. Its narrow public use is justified by the four watch sites above; it is **not** a view helper for unwrapping `:fx/context`.
2. **One current-state snapshot API.** `get-raw-state []` dereferences once and delegates to the adapter. Keep `get-state []` and `get-in-state [path]` at their current signatures (`state/core.clj:63–96,174–185`) as deprecated compatibility wrappers: respectively the same snapshot and a plain path lookup on one snapshot. Preserve `nil` before initialization and `nil` for a missing path. No subscription or whole-map cache entry. `reset-state-vals! [new-state]` uses the adapter on the **old root returned by `swap-vals!`**, retains the write guard and cache-preserving context update, and returns `[replaced-map new-state]` (`state/core.clj:108–128,162–172`).
3. **Migrate the two callback callers.** In the existing `get-ui-state` helpers (`views/components/list.clj:47–55`; `views/components/list_dnd.clj:27–30`) take `get-raw-state` at event time and do the path lookup. Do not capture a map or a bound context when installing the listener. Pass the row-drop callback's already-read drag IDs to `handle-drop!` for dispatch; its self-drop decision and its payload then use one sample. The container-drop path samples once at drop (`views/components/list_dnd.clj:49–58,205–224,242–252`). Keep the payload shape. If [04's list-lifetime work](04-list-target-lifetimes.md) has already moved a decision into its handler, do not reintroduce the read.
4. **Correct the source docstrings.** `get-raw-state` should say “one current map; no subscription or cache access.” Both legacy readers should say “compatibility snapshot; for display, subscribe through the component's supplied `:fx/context` before returning” (`state/core.clj:63–96,174–185`). Describe the old-root requirement in `reset-state-vals!` (`state/core.clj:162–165`). Correct the co-effect docstring's “via swap!” (`events/core.clj:96–104`): it **reads** a map at handling time. Replace the assertion-error comment in `services/frame_service.clj:68–70` with the actual sampling boundary: the clock passes the tick's render inputs (`services/show_clock.clj:77–88,125–135`); the two-argument frame-generation call samples them itself (`services/frame_service.clj:456–459,471–476`).
5. **Stop teaching the private key in test watches.** In the four watches in §1, apply `root-context->snapshot` separately to the callback's `old` and `new`; keep their existing comparisons and cleanup. Calling no-arg `get-raw-state` twice could observe the same later commit. Review check: a literal search for the private key across `src/` and `test/` should locate only the adapter. No new namespace or lint hook is needed.

## 7. Data examples and invariants

Let `A = {:timing {:bpm 120.0}}` and `B = {:timing {:bpm 142.0}}`. These are app maps, not hand-built cljfx contexts.

| Input / operation | Expected result |
|---|---|
| Root not initialized; then initialize with `{}` | Current snapshot `nil`, then `{}`. A missing `[:timing :bpm]` gives `nil` in either case. An incompatible **non-nil root** is an error, not either of these values. |
| Root holds `A`; take snapshot; replace with `B` | Commit returns `[A B]`. Retained map is still `A`, a fresh call returns `B`; extracting from the retained old root still returns the **identical** `A`. |
| Warm a memoized global reader and `subs/bpm` on `A`; request each again on its cache-preserving successor `B` | At this pin with both entries retained: global control `120.0`, bound BPM `142.0`, fresh external read `142.0`. Only the bound reader is appropriate for display. |
| At right-click, `[:list-ui [:cue-chain 0 0] :selected-ids]` is `#{a b}`, where `a` and `b` denote fixture item IDs | Secondary click on `b` keeps `#{a b}`; on unselected `c`, selection becomes `#{c}` (`views/components/list.clj:349–354`; `events/handlers/list.clj:64–89`). |
| One-entry LRU warmed with a counted direct subscription; read snapshots and consult the same subscription again on the **same root** | Still one evaluation. Rechecked today: `[after warm, after raw read, after legacy path read]` gave **`[1 1 2]`**. Required for all snapshot entry points: **`[1 1 1]`**. This counts cache effects, not elapsed time or frame rate. |

**Invariants:** subscriptions through the supplied render context establish the component's dependencies; snapshots do not subscribe, write, or refresh themselves. A commit advances the context generation while carrying cached entries forward. Obtain the replaced map from the atomic operation, never by rereading the current root.

## 9. Scope / alternatives considered

- A second writable map would break the atomic old/new guarantee. Subscribing to `identity` on the global root would still miss the render dependency **and** use the cache; even an unbound context is not a public no-cache unwrap ([pinned `api.clj:474–492,505–512`](https://github.com/cljfx/cljfx/blob/1.10.6/src/cljfx/api.clj#L474-L512)). Recheck upstream for a supported no-cache accessor on a future upgrade; only the adapter should have to change.
- **No new lint rule in this repair.** The two legacy production call sites are event-time reads; a `views/` ban would also flag the correct key filter. Existing write lint (`.clj-kondo/config.edn:11–38`) protects a different boundary. Reconsider a narrow rule only on evidence of an actual render-time regression that it would catch without rejecting callbacks.
- [04](00-overview.md#L35) owns stale list targets; [33–36](00-overview.md#L72-L75) own context forwarding, selector scope and cache sizing. The [app state guide](../../docs/CLJFX_STATE_MANAGEMENT.md#L5-L15), [refactoring prompt](../../prompts/refactor-clojure-file.md#L83-L95) and [diagnostic skill](../../.agents/skills/app-repl/SKILL.md#L87-L96) already distinguish snapshots from subscriptions. This page corrects the source contracts they refer to.
