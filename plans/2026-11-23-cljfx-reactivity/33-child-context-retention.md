# 33 — Keep render contexts out of child descriptions

**Status:** Implemented in `b923ddd` on `reactivity/integration` (2026-11-24); see [implementation status](00-overview.md#implementation-status-2026-11-24). Planned as: Proposed · **Last verified against:** `7b320b3` (2026-11-23, fresh headless JVMs, macOS arm64).

**Supersedes / Superseded by:** none · **Related findings:** [audit, render wiring #3 and open chain editors](../2026-11-23-cljfx-reactivity-audit.md#render-wiring-and-cache-findings); [04: list callbacks](04-list-target-lifetimes.md), [34: chain subscriptions](34-chain-editor-subscriptions.md), [36: cache working set](36-cache-working-set.md).

**Let cljfx give each child its own context.** Remove the parent's context from what the view returns, including copies inside row props and callbacks. Land 04 first: a list command must work even when rendering the sidebar is a cache hit. Source paths below are relative to `src/laser_show/`; `T/` means `test/laser_show/`.

## 1. Current behaviour

The app mounts one context atom and returns a root description with just `:fx/type` (`state/core.clj:38–51,203–214`; `app.clj:95–112`). The renderer already supplies context to children that subscribe: e.g. the Effects window returns its content without a context prop, and the content reads dialog and selection state (`views/dialogs/effect_chain_editor.clj:191–199,80–90`). Deeper in the same window, views start passing context explicitly.

## 2. Root cause and evidence

Pinned versions: cljfx **1.10.6** and core.cache **1.1.234** (`deps.edn:12–16`). [`cljfx/api.clj:603–612`](https://github.com/cljfx/cljfx/blob/1.10.6/src/cljfx/api.clj#L603-L612) installs `wrap-context-desc` and `fn->lifecycle-with-context`; [`cljfx/lifecycle.clj:509–526`](https://github.com/cljfx/cljfx/blob/1.10.6/src/cljfx/lifecycle.clj#L509-L526) puts the renderer context in **opts**. On create **and** advance, [`cljfx/lifecycle.clj:525–540`](https://github.com/cljfx/cljfx/blob/1.10.6/src/cljfx/lifecycle.clj#L525-L540) subscribes with `call-context-fn` and the incoming `desc`. The key is `[call-context-fn desc]`. **Only after lookup**, the function receives its props with `:fx/type` removed and `:fx/context` overwritten by its own bound context. Nested props are not overwritten. This is the subscription key, not the sibling identity `:fx/key`.

[`cljfx/context.clj:80–99,106–138`](https://github.com/cljfx/cljfx/blob/1.10.6/src/cljfx/context.clj#L80-L138) records a function's dependencies, caches its return value and checks those dependencies on a later generation. [`cljfx/context.clj:140–156`](https://github.com/cljfx/cljfx/blob/1.10.6/src/cljfx/context.clj#L140-L156) gives each new generation its state map and a **new cache atom seeded with the old cache value**. A re-rendered parent that forwards its context changes the child's lookup key even if all useful props are equal. From the latest cache one can follow an inherited child key → old bound context → **old state map and old cache atom** → more inherited keys. Limiting entries per atom does not break that chain. Cached return values and the list registry can also keep a context alive. Immutable states can share structure; a count of contexts is not a count of full heap copies.

## 9. Boundaries and rejected alternatives

- **04 → 33 → 34 → 36.** [04](04-list-target-lifetimes.md) owns destructive callbacks, node command addresses and removal of the render-time registry; the historical one-writer decision is recorded at `plans/2026-11-13-keyboard-focus-window-lifecycle/03-phase3-key-handling.md:290–296`. [34](34-chain-editor-subscriptions.md) owns broad chain reads (`views/dialogs/cue_chain_editor.clj:247–249`; `views/dialogs/effect_chain_editor.clj:88–90`; `subs.clj:862–875`) and stability of **other** props, including label factories (`views/components/list.clj:737–744,840–848`). [36](36-cache-working-set.md) owns capacity and whole-view measurements. Keep the production threshold at `state/core.clj:48–51` for this repair.
- **Do not use `fx/unbind-context`.** [`cljfx/api.clj:505–512`](https://github.com/cljfx/cljfx/blob/1.10.6/src/cljfx/api.clj#L505-L512) describes a debugging aid. [`cljfx/context.clj:68–87`](https://github.com/cljfx/cljfx/blob/1.10.6/src/cljfx/context.clj#L68-L87) removes the dependency recorder and parent subscription ID, **not** the state or cache. Forwarding an unbound context would still retain a generation; reading through it would lose the caller's dependency. A global snapshot (`state/core.clj:63–96`) also misses that dependency; reading a bound context in a listener is too late. Removing the prop inside the called child is already too late to change its key. No blanket tree rewrite, forced remount, cache clearing or larger cache is needed.
