## 2. Root cause: what the results actually depend on

In [the pinned context implementation](https://github.com/cljfx/cljfx/blob/1.10.6/src/cljfx/context.clj#L80-L138), the key is the function **and its arguments**. A `sub-val` leaf is rechecked on demand in a new context; a `sub-ctx` body with resident dependencies is reused when their **values** compare equal. Filtering a result after the expensive call cannot save that call. The three dependency paths are different:

```text
Vibe definitions/order + assigned cue/FX content + routing/defaults + bindings
  → lint rows (errors, warnings, info) ┬→ error count → tab label (all tabs)
                                      └→ ordered rows with text (Vibes panel)
Transport playing? ─false→ []
                   └true → intent coordinates → row/column sort ─┐
                                        labels of those cues ───┴→ playing list
Editor's ordered zone lane + rig/group names and membership + display map
  → fold text (pattern editor and Step Grid)
```

- **Lint is about the show's assignments, not which cell happens to be on.** `vibe-problems` calls `reactions/reactions` with `:own? true`: a vibe's FX set, flash FX, HIT/ACCENT cues, FLASH cue and BED (`vibes/library.clj:624–656`; `vibes/reactions.clj:283–308`). `fx-problems` walks the **items** of its assigned FX cells, counting enabled zone stages, even with the cell switched off (`vibes/library.clj:148–152,556–597`; `animation/chains.clj:68–89`). In contrast, `lint-world` passes both entire grid maps, including `[:chains :effect-chains cell :active?]` (`subs.clj:2043–2055`). Changing that one bit invalidates the full lint. **Nested** modulator `:active?`, group/item `:enabled?`, keyframe restart, pattern step/restart sources and reaction display names are real inputs (`vibes/reactions.clj:213–261,270–281`). Category and default source also consult the modulator registry (`animation/modulator_registry.clj:114–117,149–153`); see §9.
- **Errors are not just empty pools.** Order/library mismatch; a named empty or timecode cue; no playable HIT and no own HIT reaction; an assigned pattern with too few known places can all count (`vibes/library.clj:541–549,636–655,665–677`; `timeline/playback.clj:53–56`; `routing/zone_patterns.clj:319–345`). Audience reach can remove the last playable HIT: retain cue/item/track targets and column/show defaults, all maps including overrides, known groups, rig order, physical and virtual projector tags/membership, and the vibe's permission (`routing/targets.clj:305–322`; `vibes/library.clj:77–138,193–214`). Also keep **non-error** inputs: names and zone labels for messages, the committed active map for stage warnings, role bindings for learned/unheard rows and Zone step bindings for pattern hints (`vibes/library.clj:468–489,513–539,551–575,609–622,678–685`; `routing/zone_patterns.clj:301–307,325–345`). A warning changing with the badge still at zero is a successful refresh.
- **Two other readers share today's `lint-world`.** The checklist's “Make cues” scans **all** cue cells, including ones in no vibe; its HIT and controls steps use playable pools and learned roles (`subs.clj:2085–2088`; `vibes/library.clj:687–701`; `views/tabs/vibes.clj:33–42`). The edited reaction list uses the **edited** ID and `:own? true` (`subs.clj:1870–1874,2062–2066`; `views/tabs/vibes.clj:206–215`). Perform's separate `vibe-reactions` uses the **playing** ID and the default `:own?` false/nil: live on-grid cells really do affect pad names (`subs.clj:1807–1832,1850–1855`; `vibes/reactions.clj:290–307`). Do not strip activation from the stored chains or from Perform's inputs.
- **Playing list:** `ex/active-cues` is a cheap map lookup (`state/extractors.clj:111–121`), but the current `sub-val` extractor sorts its keys. The status then selects six fields from `cell-display-data`, whose dependencies also include selection, activity and the whole cue chain (`subs.clj:250–291,310–326`). The label needs the cue's name, first stored preset, preset count and timeline classification (`views/components/grid_cell.clj:58–72`; `animation/cue_chains.clj:59–75`); coordinates come from membership. A pause/seek/retrigger of an existing intent is not a membership change. This is work done during validation, not a late/lazy read of a bound context.
- **Pattern fold:** both callers pass whole params (`views/components/zone_pattern_editor.clj:393–405,451–456`; `views/dialogs/step_grid_editor.clj:45–49,78–83`). Of those params the formatter reads **only** `:zones`. It preserves lane order, expands `:lane/lasers` against enabled, non-excluded projectors, resolves known refs through the map, and prints laser/group/map names; zones use letters, not user labels (`routing/zone_patterns.clj:276–280,296–304,359–402`; `routing/zone_remap.clj:122–137`; `routing/rig.clj:118–143,269–288,429–438,453–463`). The fold calls `effective-map-id` at beat `0.0` with a **nil cycle pick**: a pending map already due at zero can count, otherwise the manual ID, with unknown-ID fallback (`routing/zone_maps.clj:73–76,90–104`). Unlike full panel lint's existing active-only slice (`subs.clj:2052–2054`), the fold currently receives the pending slot too. Neither is reading the live tick's cycle pick.

## 4. Changes per namespace

**`laser-show.subs` (`subs.clj:1–26`):** use stable named `sub-ctx` functions with cheap addressed `sub-val` leaves. Finish all dependent reads before returning a concrete map, set or vector ([app guide](../../docs/CLJFX_STATE_MANAGEMENT.md#reactive-state-in-this-app)).

1. **Vibes.** Replace the `[state]` extractor `lint-world` with a `[context]` subscription. Its output keeps the state shape consumed by `library/lint`; `vibe-lint` subscribes to it. No visibility gate and no second implementation of the error rules.
   - **NEW** `lint-vibes [context]`: from `[:config :vibes :order]` and `:library` (`subs.clj:1673–1676`; `vibes/library.clj:630–636,665–676`), retain the order **as-is**, every original library key, and each entry's `:id`, `:name`, `:allow-audience?`, HIT/ACCENT `:cells`, `:flash` cue/FX, `:bed` and `:fx`. This excludes unrelated preferences/colour/energy without hiding duplicate order entries or missing/orphan definitions.
   - **NEW** `vibe-fx-content [context col row]`: read the addressed effect chain and omit **only its top-level** `:active?`; nil stays nil. **NEW** `vibe-owned-chains [context vibe-id]`: use that vibe's slots to collect addressed cue chains and these structural FX chains into `{:cue-chains {...} :effect-chains {...}}`. A missing assigned cue still reads as empty. Dynamic dependencies follow assignment edits; an unassigned FX cell has no subscription here. A switch on an assigned cell can recheck its small projection but must not rerun the linter.
   - For full lint, combine owned chains across library IDs, plus `lint-vibes`, shared audience routing **including virtual projectors**, trigger map, `[:zones :labels]` and **only** `[:zone-map :active]`; preserve `[:config :default-target]` when composing nested config (`subs.clj:2038–2060`). Feed edited reactions just the edited definition and its owned chains. Feed the checklist the definitions, audience routing, bindings and the **whole cue grid**; it needs no FX chains. This replaces all three direct `sub-val lint-world` uses. A single `library/lint` result still serves both the tab bar and the panel.
2. **Playing list.** **NEW** `active-cue-cells [context]` → eager unordered set of keys, behind `sub-ctx`, from the cheap `ex/active-cues` leaf. Change private `cue-cells-in-grid-order` to `[context]` → eager vector sorted by `[row col]` over that **set**. Changes inside intent values may rebuild the set but an equal set does not sort again. Keep `playing-cues`' false branch `[]`. For each sorted address in the true branch, subscribe to **NEW** `cue-label-data [context col row]`: the addressed chain's name and #10's content facts, without selection or activation. Promote the existing picker label projection to this shared selector; keep `vibe-pick-label`'s public result. Add the coordinates and return exactly the existing six status fields (`subs.clj:315–326`); do not truncate its vector to the two entries named by the status bar.
3. **Fold.** Change `pattern-fold`'s public subscription argument to `[context zones]`, an **ordered lane vector**, not params, a set, an expanded lane, or an editor ID. **NEW** `pattern-fold-world [context]` is the display-routing input for this line. Retain projector IDs, names, fallback-order inputs (host and service), enable/exclude flags and memberships; rig order/middle policy; group IDs/names; and the map resolved by the existing beat-zero/nil-cycle rule, including its ID, name, lanes and overrides (`routing/rig.clj:118–143,221–246,269–288,292–324`; `routing/zone_maps.clj:42–57,90–104`). Supply the resolved ID as active and its definition if custom to the formatter; form its names using the existing target-group/name functions on that world with empty label overrides. This isolates the fold from bindings, zone labels and unrelated pattern params. Keep the broader `pattern-world` and `names-ctx` for the editor's **warnings** and other displays; e.g. Zone step learn genuinely changes a warning (`subs.clj:1000–1009,1174–1184`; `routing/zone_patterns.clj:306–345`).

**`laser-show.views.components.zone-pattern-editor`** (`views/components/zone_pattern_editor.clj:385–405,441–459`): pass the current editor params' `:zones` vector to the subscription at line 453. **`laser-show.views.dialogs.step-grid-editor`** (`views/dialogs/step_grid_editor.clj:45–49,78–83`): pass **the displayed grid's** `[:params :zones]` at line 82. A non-grid pattern is projected through `as-grid` first, which can replace `:lane/lasers` with lettered rows (`subs.clj:1334–1349`; `routing/step_grid.clj:242–256,266–284`). Change **both callers at the cache boundary**; an outer subscription still keyed by whole params retains all 64 keys even if it delegates to a narrow inner one.

## 9. Scope and order

Keep one linter. A second, approximate “count errors” algorithm could miss errors contributed by playable-cue filtering or by pattern warnings. Keep the live Perform path from [12](12-audience-indicators.md), the stored-content rule from [10](10-grid-click-intent.md), and selection fan-out from [35](35-grid-subscription-fanout.md) distinct. [17](17-registry-descriptors.md) owns publishing registry changes; when integrating, a changed modulator category/default used by a reaction must invalidate its result, not wait for an unrelated grid toggle. This plan changes neither map-selection policy ([29](29-effective-map-selection.md)) nor output routing.

**Size the cache after narrowing inputs.** Record [36](36-cache-working-set.md)'s baseline first; after 33–35 and 37, repeat its same Grid, Vibes and open-editor workloads before choosing the production bound. The saved [whole-Grid probe](../probes/cljfx_reactivity_2026_11_23.clj#L73-L103) counts view calls; it is not the source of the three isolated counts in §1. Neither a bigger LRU nor a stable label establishes that the expensive selector body stopped running.
