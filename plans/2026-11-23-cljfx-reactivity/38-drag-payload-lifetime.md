# 38 · End the drag payload with the gesture that supplied it

**Status:** Proposed · **Last verified against:** `7b320b3` (source trace and synthetic JavaFX probe, 2026-11-23).

**Supersedes / Superseded by:** none · **Related finding:** [grid-review supplement, finding 38](00-overview.md#L79). This page owns the lifetime of the payload **after a drag starts**.

Source paths below are relative to `src/laser_show/`. `C/` = `views/components/`, `V/` = `views/components/visual_editors/`, `T/` = `test/laser_show/`.

## 1. Current behaviour

`start-drag!` writes a tagged payload to the process-wide `!dragging` atom **before** asking JavaFX for a dragboard, then writes the encoded string under a private format. `end-drag!` removes the entry by type. `read-payload` first requires the advertised format; a string is parsed and validated, but **any non-string** causes a lookup by type alone (`C/drag_drop_cell.clj:32–52,67–118`). The wire payload contains coordinates or IDs, not the contents being moved.

| Production source | Consumers and completion |
|---|---|

The inner stack pane starts only when the rendered cell has content (`C/grid_cell.clj:133–146,180–198,234–242,377–388,478–486,535–546`; `C/drag_drop_cell.clj:124–137`). | Both grids check **only the format on over**. **Reproduced without a native drag.** In a fresh headless JVM, passed real drag-detected events to the generic cell's callbacks. A test stack pane returned the in-memory dragboard from `T/ui_test/testfx.clj:414–433` instead of starting an OS gesture. After 102 starts there were **two entries**, last cue `[2 1]` and last effect `[4 2]`. A *different* board advertising the matching format and returning `nil`, with no gesture source, produced a completed drop and a recorded move to `[7 3]` **from those old coordinates**, on both grids. Readable native `[5 0]` won; a malformed string and a board without the format dispatched nothing. Calling `end-drag!` made the hidden drop fail (the format-only hover still accepted). The probe recorded dispatches, not a native cancellation or a changed show.

## 2. Root cause and consequence

A drag **type** identifies an encoding, not the particular gesture. Source completion is missing for both grids; a failed native start can also leave an entry. Cancellation, release outside an accepting target and removal of the source have no successful target drop to clean up. Tabs replace their content, closing a dialog removes its stage, and stopping the app unmounts the renderer (`views/root.clj:66–79,287–290`; `app.clj:324–327`); the global atom has none of those lifetimes.

This is **bounded stale data, not a cumulative leak per drag, cell or render**: `assoc` overwrites one value per type, four types at these production callers. The two grid entries can remain indefinitely. The separately cached `DataFormat`s are intentionally reusable (`C/drag_drop_cell.clj:67–86`). The risk is moving the *current occupant* of stale coordinates, potentially overwriting a destination and retargeting bindings/vibes. Both move handlers read the current source entry and do nothing if it is absent (`events/handlers/grid.clj:133–155`; `events/handlers/effects.clj:79–91`). Ordinary external text/files without the private format cannot trigger this fallback. How often a native platform hides the private content is **unverified**.

## 4. Changes per namespace

1. **`laser-show.views.components.drag-drop-cell`** (`C/drag_drop_cell.clj:1–27,78–118,124–179`). Replace `!dragging` with **one active entry on the originating JavaFX Scene** (§5). At each start retire any prior entry on that scene. Publish only after `startDragAndDrop` returns and `setContent` succeeds; false or exception leaves no entry or listeners. Keep the successful Dragboard return. **NEW private** `open-dragboard! [source modes]` isolates just the native start so tests can exercise the real source node and `setContent` with a fake board.
   - Change `end-drag!` to take the source node. Run it synchronously on source `DRAG_DONE`, whether accepted, refused, released outside or cancelled with Escape (nil transfer mode); finish only the owning node's entry. **NEW private** `retire-drag! [scene expected-entry]` compares entry identity, removes that entry and unregisters its listeners once. Also use it on replacement, and from listeners attached **only during the drag**: the origin leaves its scene, the scene loses/changes its window, or that window hides. Each listener captures its original scene and entry. Unwind partial setup on failure. Target exit and ordinary focus transfer are not terminal: a drag can leave and re-enter. If the platform sends *no* terminal signal while the source remains mounted, a foreign drag still cannot use the slot; the next start replaces it before use. There is no queued application “done” event.
   - Change `read-payload` to take `[drag-event drag-type valid?]`. Check the board's private format first. **If the native value is a string, its parse result is final**, including `nil` for malformed/invalid strings. Reject a present value of the wrong representation. Only an advertised format with a **nil** value can use the local copy. Obtain the *origin* with `DragEvent.getGestureSource`, not `getSource` (the handling target); require a Node still attached to its live scene/window, the exact recorded source instance and the requested type. Missing/foreign origin → no fallback. Native valid data still works without any local origin, as in the existing target-only tests. Do not compare Dragboard object identity: in the pinned JavaFX `28-ea+11` (`deps.edn:107–113`), `Scene.java:3219–3227` wraps the clipboard again on target entry; over/drop carry the gesture source (`Scene.java:3483–3495,3537–3540`, checked in the dependency's bytecode).
2. **`laser-show.views.components.grid-cell` / `vibe-picker`** (`C/grid_cell.clj:103–115,144–151,180–200`; `C/vibe_picker.clj:65–87`). Put `:on-drag-done` on the **same stack pane** as detection; cleanup must still run if the source cell became empty after a move. Include all four drag props only when there is a drag configuration; omit the keys altogether otherwise. Remove the picker's now-redundant `undraggable` stripping wrapper. The cue/effect content predicate still gates **start**, not cleanup or the ability of an empty destination to take a drop.
3. **`tabbed-bank`, `rig-strip`** (`C/tabbed_bank.clj:58–69`; `C/rig_strip.clj:437–455`): pass the originating node on done; preserve the bank's independent disarm and the rig's bar. Pass the native event on payload reads, including the generic cell drop in `C/drag_drop_cell.clj:167–179`.
4. **Timeline adapters** (`V/canvas_interaction.clj:171–180,352–378`; `V/timeline_editor.clj:465–486,968–970`; `V/timeline/header.clj:128–160`; `V/timeline/device_chain.clj:102–117,143–156`): pass the `DragEvent` through the two canvas over/drop callbacks in place of the board-only argument; update their documented contract. Header and chain already have the event. Use it synchronously at each read, forwarding only plain data to preview logic and dispatch. Keep format-only checks where they exist, COPY/MOVE negotiation and each target's own exit feedback.

## 7. Data cases and invariants

| Input (independent cases; `A`, `B` are different source Nodes) | Required outcome |
|---|---|
| 1. `A` starts `:grid-cell [2 1]`; that format is advertised, value `nil`, origin `A`, drop at `[7 3]` | `{:event/type :grid/move-cell :from-col 2 :from-row 1 :to-col 7 :to-row 3}` once. Done removes the entry. Repeat the hidden drop: format-only over can accept, completion false, zero dispatches. Same rule for `:effects-cell`. |
| 2. Same live `A`; board has a valid string for `[5 0]`, or instead `"{"`, a wrong marker, negative coordinate, or a non-nil non-string | Valid → move **`[5 0]`**, also with no gesture source. Each invalid native value → no move. Never repair native data with `[2 1]`. |
| 3. `A` still active; matching format hidden with origin `nil` or an unrelated node; separately, text/files only, or only the other grid's format | No payload in all cases. No move, timeline add or rig reorder. A format-only target may offer MOVE in the first case, but cannot complete it. |
| 4. `A` ends via Escape, rejected/outside release, source detach or window hide; `B` starts same type `[4 2]`; old `A` cleanup fires again | No edit for cancellation; hidden `A` cannot read, hidden `B` reads `[4 2]`. Closes/reopens and repeats do not resurrect `[2 1]`. A failed new start leaves no usable fallback. |
| 5. Bank button starts `{:kind :effect :id :scale :category :shape}`; its private format is hidden on over; move between valid lane/header/chain targets, then drop | Current button supplies the highlight/insertion preview; leaving one target clears its preview, not the drag. Only the final target dispatches an add. Done releases the entry and disarms the button; the next click adds once. |

## 9. Dependencies and scope

No prerequisite. This is not [16's press/paint undo transaction](16-gesture-undo-boundaries.md#L35-L41): a cell move is one command on drop. [04's list callback lifetime](00-overview.md#L35) and [20's document-bound completions](00-overview.md#L56) have different owners. This fix identifies the source of hidden data; it does not make a coordinate a persistent entity ID or fence an already-dispatched command across document replacement. A type-wide clear on drop would miss cancellations and can erase another source's data; a timeout cannot identify the origin. Neither is needed for the scene-owned slot.
